# 헤르메스를 거치지 않는 채팅 기능

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1003-03 |
| 작성일 | 2026-10-03 |
| 대상 | 위키 채팅을 헤르메스 도구로 보낸 뒤, 같은 턴 입구에 남은 가로채기 |
| 목적 | 기획상 헤르메스가 필수인데, 사용자 문장이 모델에 닿기 전에 끝나는 기능이 아직 있는지 |
| 조사 범위 | `_execute_user_turn`, 메일·캘린더 패널 챗, 실행 요청, 설정에서 헤르메스를 끄는 경로 |
| 하지 않은 일 | 아래 남은 가로채기의 코드 수정, 사이드바 버튼이 헤르메스를 타게 바꾸는 일 |

위키 쪽은 이번 구현으로 빠졌다. `wiki_requests_go_to_hermes()` 가 참이면 `try_wiki_command` 와 `_try_local_wiki_save` 는 호출되지 않는다. 저장·목록·열기·삭제·재가공·폴더 이동은 `HermesChatWorker` 가 고르는 `wiki.*` 도구다.

---

## 1. 결론

헤르메스가 켜져 있으면(`hermes_enabled`, 기본값 참) 메인 채팅의 위키·IDE 짧은 문장·PDF 저장·화면 전환·새 확장 설치는 모델로 간다. 그 상태에서 문장만 보고 턴을 끝내는 곳은 하나다. 진행 중인 확장 설치가 비밀 값이나 디렉터리를 기다리는 답이다.

헤르메스 설정이 거짓이면 그 아래 다섯 갈래가 다시 로컬로 닫힌다. IDE 켜기·끄기, PDF 저장, 새 확장 설치, 홈·마이크·메일·캘린더·위키 화면 열기, 그리고 코드 실행 요청의 로컬 실행이다. 도구 호출용 `settings.set` 은 `hermes_enabled` 를 거짓으로 바꾸는 요청을 거부한다. 설정 파일이 이미 거짓이면 그 분기는 그대로 탄다.

메일·캘린더 화면의 우측 챗은 메인 턴을 떠나도 `HermesChatWorker` 로 들어간다. 버튼을 누르는 사이드바 아이콘은 채팅이 아니라서 헤르메스를 쓰지 않는다.

---

## 2. 구조

```
사용자 문장
  _execute_user_turn
        │
        ├─ wiki_requests_go_to_hermes() 가 참
        │     try_wiki_command, _try_local_wiki_save 는 호출하지 않음   ← 이번 구현
        │
        ├─ hermes_enabled 참
        │     ├─ 확장 설치가 답을 기다리는 중
        │     │     _try_local_extension_install(allow_new=False)
        │     │     비밀·경로·취소면 여기서 return                          ← 남은 가로채기
        │     │     새 설치 문장이면 False. 모델로 계속
        │     └─ 그 외 메인 챗 → HermesChatWorker
        │
        └─ hermes_enabled 거짓
              ├─ _try_local_ide_control          IDE 켜기·끄기 짧은 문장
              ├─ _try_local_pdf_save             PDF 저장 의도
              ├─ _try_local_extension_install    새 설치 포함
              ├─ _try_local_workspace_control    홈, 마이크, 메일·캘린더·위키 화면
              └─ 그 외 → API 직접 호출. 헤르메스 도구 없음
                    실행 요청은 _try_reveal_local_vibe_code 가 로컬 run
        │
        ▼  (메일·캘린더 워크스페이스에 있을 때, 위 분기를 통과한 뒤)
_route_to_workspace_chat
  패널 챗 → hermes_enabled 이면 HermesChatWorker
            거짓이면 「Hermes 에이전트가 필요합니다」
```

사이드바의 메일·캘린더·위키·IDE 아이콘은 이 트리 밖에 있다. 클릭이 핸들러를 바로 부른다.

---

## 3. 확인한 사실

`iris/config/settings.py` 의 `hermes_enabled` 기본값은 `True` 다.

`iris/ui/control_actions/settings.py` 는 `hermes_enabled` 를 거짓으로 넣는 `settings.set` 을 `hermes_enabled cannot be disabled` 로 거절한다. 설정 화면이 저장 파일을 직접 고치는 경로는 이 함수가 아니다.

`agent_local_gate.hermes_owns_local_intents` 는 그 불리언 하나다. 참이면 `_execute_user_turn` 의 `else` 가지(IDE·PDF·새 확장·화면 문구)는 타지 않는다.

확장의 `allow_new=False` 가지는 헤르메스가 켜져 있어도 맨 앞에서 돈다. 새 URL 설치 문장은 `return False` 라 모델로 간다. 이미 쌓인 `_pending_ext` 에 대한 취소·비밀·디렉터리 답만 로컬에서 끝내고 `return True` 다.

메일 패널 `_on_email_chat_send`, 캘린더 패널의 대응 함수는 헤르메스가 꺼져 있으면 오류 문장으로 끝내고, 켜져 있으면 `HermesChatWorker` 를 만든다. 캘린더 답이 온 뒤 `parse_calendar_ops` 는 모델이 이미 쓴 문장에서 조작을 읽는다. 사용자 문장을 모델 전에 닫지는 않는다.

`_try_reveal_local_vibe_code` 의 `run_locally` 는 `hermes_owns_local_intents` 가 거짓일 때만 `is_run_request` 를 탄다.

## 4. 코드 리뷰

### 4.1 헤르메스가 켜져 있을 때 남는 입구

`_execute_user_turn` 은 위키 게이트 다음에 `owns` 가 참이면 `_try_local_extension_install(turn, allow_new=False)` 만 본다.

`_try_local_extension_install` 은 문장이 새 설치로 파싱되고 `allow_new` 가 거짓이면 대기 상태를 비우고 `False` 를 돌려 준다. 대기 중인 설치가 있고 문장이 취소·비밀·경로이면 설치를 이어 하고 턴을 닫는다. 이번 질문에서 이 경로가 한 일: 설치 중간에 사용자가 값을 치면 그 문장은 모델이 보지 않는다. 막지 못한 이유: 대기 상태를 모델 도구의 다음 호출로 넘기는 자리가 없다.

### 4.2 헤르메스 설정이 거짓일 때의 다섯 갈래

같은 함수의 `else` 다.

`_try_local_ide_control` 은 IDE·컴패니언을 켜거나 끄는 문장 전체가 정규식에 맞을 때만 아이콘과 같은 핸들러를 부른다.

`_try_local_pdf_save` 는 `is_pdf_save_intent` 가 참이면 PDF 워커를 돌리고 턴을 닫는다.

`_try_local_extension_install(allow_new=True)` 는 새 GitHub 설치 문장도 로컬에서 처리한다.

`_try_local_workspace_control` 은 홈, 마이크, 메일·캘린더·위키 화면을 여는 짧은 문장만 맞춘다. 「위키에 저장」처럼 화면이 아닌 문장은 여기 정규식에 안 맞는다.

`_launch_chat_turn` 은 이 분기를 통과한 뒤 헤르메스가 꺼져 있으면 API 를 직접 부른다. `iris_invoke` 가 없다.

### 4.3 패널 챗과 버튼

`_route_to_workspace_chat` 은 워크스페이스가 메일이나 캘린더일 때 메인 챗 대신 패널로 넘긴다. 패널은 4.2가 아닐 때 헤르메스 워커를 연다. 사용자 문장은 모델을 거치지만, 메인 채팅의 위키 완료 게이트와는 다른 워커다.

사이드바 `_on_email_icon`, `_on_calendar_icon`, `_on_obsidian_icon`, IDE 컴패니언 진입은 클릭 핸들러다. 채팅 문장을 해석하지 않는다.

### 4.4 하지 않은 일

- 위키 분류기·검색의 임베딩은 채팅 입구가 아니다. 도구가 노트를 쓸 때 폴더를 고른다.
- 설정 대화상자가 `hermes_enabled` 체크를 저장 파일에 직접 쓰는지는 이 턴 입구 조사에서 실행해 보지 않았다. 도구 경로만 거절을 확인했다.

---

## 5. 빈 자리

헤르메스가 켜진 채팅에서 비어 있는 것은 확장 설치의 대기 답뿐이다. 그 문장도 모델이 `extension.install_github` 를 다시 부르게 하면 로컬 대기가 필요 없다.

헤르메스 설정이 거짓일 때의 IDE·PDF·화면·실행 분기는 기본값과 `settings.set` 거절과 어긋난다. 설정 파일이 거짓인 PC 에서는 그 문장들이 여전히 모델 전에 끝난다.
