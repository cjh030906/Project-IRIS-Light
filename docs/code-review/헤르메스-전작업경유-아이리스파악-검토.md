# 헤르메스가 아이리스 작업을 모두 맡고, 아이리스를 파악할 수 있는지

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1003-04 |
| 작성일 | 2026-10-03 |
| 앞 문서 | [헤르메스를 거치지 않는 채팅 기능](헤르메스-미경유-채팅기능-현황.md) (IRIS-REV-2026-1003-03) |
| 목적 | 아이리스에서 일어나는 일을 전부 헤르메스 에이전트에 태울 수 있는지, 그 장단점, 아이리스 MCP 안의 툴·스킬이 아이리스를 얼마나 아는지, 그렇게 만들어도 되는지를 코드로 가른다 |
| 조사 범위 | `iris-control` MCP 세 도구, 컨트롤 액션 122개, `integrations/hermes-skills/iris-control` 스킬 10개, Hermes MEMORY 넛지, 사이드바 클릭 |
| 하지 않은 일 | 스킬·넛지 문장 수정, 카탈로그 인자 스키마 추가, 버튼 클릭을 모델 턴으로 바꾸는 일 |

03은 사용자 **문장**이 모델에 닿기 전에 끝나는 입구만 봤다. 이 문서는 그 다음이다. 문장이 모델에 들어간 뒤 헤르메스가 아이리스를 어떻게 잡고, 문장이 아닌 클릭·창·에디터는 그 길에 없는지를 본다.

---

## 1. 결론

아이리스가 하는 일을 **전부** 헤르메스 에이전트 턴으로 보낼 수는 없고, 보내면 안 된다. 보내야 하는 것은 사용자가 말로 시킨 일이다. 그 길은 이미 `hermes_enabled`(기본 참)일 때 메인 채팅의 기본이다. 03에서 그때 문장만 보고 턴을 닫는 곳은 진행 중인 확장 설치의 비밀·경로 답뿐이다.

헤르메스가 아이리스를 다루는 손은 MCP 서버 `iris-control`의 도구 **세 개**다. `iris_get_state`, `iris_get_catalog`, `iris_invoke`. 화면을 바꾸는 이름 122개는 그 안에 따로 등록된 MCP 도구가 아니다. `iris_invoke`의 `action` 인자로 넘어가고, 사이드바 아이콘과 **같은 핸들러**가 실행한다.

스킬은 MCP 도구가 아니다. `integrations/hermes-skills/iris-control/` 아래 `SKILL.md` 10개가 절차 설명서다. 기동 동기화가 `%LOCALAPPDATA%\hermes\skills\iris-control`으로 복사한다. 같은 역할을 하는 문장이 `hermes_memory_nudge.py`의 MEMORY 블록에도 있다. 설명서가 두 벌이다.

122개 중 스킬 본문에 이름이 나오는 것은 51개, 넛지까지 합치면 63개다. 나머지 59개는 `iris_get_catalog`가 돌려주는 한 줄 요약으로만 발견된다. 인자 이름·모양은 카탈로그에 없다. 그래서 헤르메스는 아이리스 **소스**를 아는 것이 아니라, 카탈로그와 스킬이 적어 둔 조작만 안다.

이렇게 만드는 것이 맞다. 말 → 헤르메스 → 세 도구 → 같은 핸들러. 버튼·창 크롬·설정 폼은 그 핸들러를 직접 부른다. 버튼까지 모델에 태우거나, 122개 절차를 프롬프트에 전부 넣는 쪽은 만들지 않는 편이 맞다.

---

## 2. 구조

말이 아이리스를 움직이는 길과, 클릭이 같은 핸들러에 닿는 길은 갈라진다.

```
[말]
사용자 문장
  _execute_user_turn
        │
        ├─ hermes_enabled 참
        │     확장 설치 대기 답만 로컬에서 닫힘          ← 03
        │     그 외 → HermesChatWorker
        │           헤르메스 게이트웨이 (모델)
        │                 │
        │                 ├─ 스킬 10개 + MEMORY 넛지     ← 설명서. 실행 아님
        │                 │
        │                 └─ MCP stdio  iris.mcp.iris_control_stdio
        │                       도구 3개만
        │                         iris_get_state    GET  /v1/state
        │                         iris_get_catalog  GET  /v1/catalog
        │                         iris_invoke       POST /v1/invoke
        │                              │
        │                              ▼
        │                       control_surface (로컬 HTTP, 토큰)
        │                       ActionRegistry.invoke
        │                       control_actions/*.py 핸들러
        │
        └─ hermes_enabled 거짓
              로컬 정규식 다섯 갈래 후 API 직접 호출     ← 03
              iris_invoke 없음

[클릭·창]
사이드바 메일·캘린더·위키·IDE, 창 최소화, 설정 화면
  핸들러를 바로 호출
  헤르메스 턴을 만들지 않음
  다만 등록된 액션과 같은 함수를 쓰는 버튼은 결과가 같다

[도구 안]
wiki.write_user_note / wiki.import_content 가 고른 뒤
  폴더 분류·임베딩은 핸들러 안에서 돈다
  헤르메스가 노트를 한 줄씩 쓰지 않는다
```

이번 질문의 갈림은 「말」과 「클릭」이다. 말을 전부 헤르메스에 태우는 것은 위 트리의 왼쪽이다. 클릭까지 태우는 것은 오른쪽 가지를 없애고 모든 입력을 게이트웨이로 보내는 다른 프로그램이다.

## 3. 확인한 사실

### 3.1 도구는 세 개, 액션은 122개

`iris/mcp/iris_control_stdio.py`의 `TOOLS`는 `iris_get_state`, `iris_get_catalog`, `iris_invoke`뿐이다. 헤르메스가 붙일 때 이름은 `mcp__iris_control__` 접두사가 붙는다. 넛지 1번이 그 철자를 고정한다. 접두사 없는 `iris_invoke`는 게이트웨이가 도구로 인식하지 못한다.

`iris_invoke`는 `action`과 `args`만 받는다. HTTP `POST /v1/invoke`가 `ActionRegistry.invoke`로 넘긴다. `GET /v1/catalog`는 UI 스레드를 타지 않고 레지스트리 목록만 돌려준다. `GET /v1/state`는 액션 `get_state`를 15초 안에 부른다.

`action_catalog.json`은 이름 122개다. 필드가 `name`, `summary`, `risk`, `confirm_required`뿐이다. 인자 스키마는 없다. `iris/ui/_check_control_action_split.py`는 이 파일이 `register()`와 같은 122건 스냅샷이라고 적는다. 이번 조사에서 그 검사를 다시 실행하지는 않았다. `register()` 문자열 118개에 `workspace.py`의 소셜 스텁 루프 4개(`open_instagram`, `open_discord`, `open_kakao`, `open_telegram`)를 더하면 122와 맞다. 그 네 개의 요약은 「준비 중」이다.

`confirm_required`가 참인 액션은 `chat.clear_history`, `email.add_account`, `email.remove_account`, `email.send`, `learning.run`이다. `args.confirm`이 없으면 `invoke`가 거절한다.

`settings.set`으로 `hermes_enabled`를 거짓으로 넣는 호출은 거절된다. 03과 같다.

### 3.2 스킬과 넛지는 설명서다

`SKILL_NAMES`(`hermes_iris_control_sync.py`)는 다음 10개다. 동기화가 저장소에서 Hermes 홈으로 복사한다.

| 스킬 | 카탈로그 이름을 적은 개수 | 하는 말 |
|---|---|---|
| iris-work-start | 6 | 컴패니언으로 폴더를 연다. 터미널 `cursor` 금지 |
| iris-work-end | 7 | 컴패니언을 끄고 홈으로 |
| iris-vibe-code | 5 | `project.write_file`, `project.run` |
| iris-wiki | 9 | 저장·이동·검색. 말만 하고 저장했다고 하지 말 것 |
| iris-email | 5 | 목록·읽기·작성·보내기 |
| iris-calendar | 8 | 일정과 캘린더 화면 |
| iris-emulator | 15 | 에뮬레이터 조작 전부 |
| iris-mobile-mcp | 9 | 에뮬레이터와 겹친다. 휴대폰 MCP를 가리키는 절차 |
| iris-learning | 4 | 학습 시작·중지 |
| iris-session-status | 0 | `iris_get_state`만. 액션 이름 없음 |

10개를 합쳐 카탈로그와 겹치는 이름은 51개다.

`hermes_memory_nudge.py`의 마커는 `iris-control-nudge-v19`다. Hermes MEMORY에 붙는 고정 문장이고, 여기서 카탈로그 이름이 맞는 것은 35개다. 스킬에 없고 넛지에만 있는 것이 있다. `wiki.import_pages`, `wiki.move_notes`의 금지(다시 쓰지 말 것), `extension.install_github`, `ide.marketplace_search`, `ide.marketplace_install`, `ide.project_log`, `note.export_pdf`, `project.write_image_code`, `voice.mic_on` / `mic_off`. 스킬 `iris-wiki`는 이동을 적지만 마켓플레이스·확장은 적지 않는다.

스킬과 넛지를 합쳐도 이름이 안 나오는 액션은 59개다. `iris_invoke` 설명문 자체가 그중 일부를 적는다. `chat.new_session`, `chat.list_sessions`, `chat.open_session`, `profile.set`, `ide.set_project_root`, `ide.open_file`, `voice.mic_status`. 설명서 어디에도 절차가 없는 묶음은 아래다.

- 창: `window.minimize`, `window.show`, `window.toggle_maximize`
- 설정·프로필 화면: `settings.get`, `settings.set`, `profile.get`, `ui.open_settings`, `ui.open_mcp`, `ui.open_skills`, `ui.open_user_profile`
- 루틴 6개: `routine.create`부터 `routine.run`까지
- 학습 조회: `learning.get`, `learning.list`, `learning.toggle`, `learning.run_status`
- 위키 읽기·삭제·재가공: `wiki.read_note`, `wiki.delete_note`, `wiki.reprocess_note`
- IDE 고르기: `ide.list`, `ide.pick_open_file`, `ide.pick_open_folder`, `ide.set_preferred`, `ide.toggle_companion`
- 메일 계정·폴더: `email.add_account`, `email.remove_account`, `email.list_accounts`, `email.set_account`, `email.select_folder`, `email.set_category`, `email.refresh_inbox`, `email.open_message`
- 그 외: `diagram.render`, `chat.attach`, `chat.stop`, `chat.set_model`, `chat.clear_history`, `project.find_similar`, `activity.log`, `notify.add_alert`, `voice.toggle_mic`, 소셜 스텁 4개

`get_state`가 돌려주는 런타임은 세션 스냅샷이다. `ui_mode`, `workspace_mode`, `project_root`, `project_parents`, IDE 세션, `hermes_online`, `hermes_enabled`, 모델 이름, 메일 계정 요약, 캘린더의 년·월·선택일, 마이크, 에뮬레이터, IRIS IDE 컨텍스트. 위키 목록, 열린 에디터 탭, 설치된 스킬 목록, 설정 파일 전체는 여기 없다.

휴대폰용 `mobile-mcp`는 `iris-control`과 다른 서버다. `npx @mobilenext/mobile-mcp`다. 아이리스 화면 핸들러가 아니다.

### 3.3 말이 아닌 일은 에이전트를 타지 않는다

사이드바 `_on_email_icon`, `_on_calendar_icon`, `_on_obsidian_icon`, IDE 컴패니언 진입은 클릭 핸들러다. 03과 같다. 채팅 문장을 만들지 않으므로 헤르메스를 부르지 않는다. 등록된 워크스페이스 액션과 같은 일을 바로 한다.

IRIS IDE 안의 타이핑, 탭 클릭, 터미널 키 입력은 Theia 프로세스다. 헤르메스가 건드릴 수 있는 것은 `ide.*`, `project.*`로 등록된 조작이다. 에디터의 모든 입력이 MCP로 올라오지는 않는다.

위키 폴더 분류는 `wiki.write_user_note`가 성공한 뒤 핸들러가 한다. 헤르메스가 분류 모델을 대신하지 않는다.

## 4. 코드 리뷰

### 4.1 손 — MCP 세 도구

`iris_control_stdio._handle_tool`은 이름 세 개만 HTTP로 바꾼다. 아이리스가 꺼져 있으면 `Iris control unreachable … Start Iris Light first.`를 돌려준다. 헤르메스는 아이리스 프로세스 없이 화면을 움직이지 못한다.

`ControlSurface`의 `do_POST /v1/invoke`는 액션 이름으로 `call_registered`를 부른다. 마켓플레이스 설치와 파일 스트리밍만 타임아웃이 180초다. 나머지는 15초다.

`ActionRegistry.catalog`는 `register()`에 넘긴 요약·위험·확인 플래그만 직렬화한다. 이번 질문에서 이 경로가 한 일: 모델이 아이리스를 「파악」할 때 받을 수 있는 목록의 한계가 여기 있다. 막지 못한 이유: 인자 이름이 요약 문장에 우연히 있을 뿐, 스키마로 검증되지 않는다. 모델은 요약을 읽고 `args`를 추측한다.

`_register_actions`는 세션·IDE·프로젝트·프로필·워크스페이스·에뮬레이터·학습·루틴·설정·메일·위키·채팅·에이전트 턴 등록을 한곳에 모은다. 사이드바와 MCP가 이 레지스트리를 공유한다.

### 4.2 설명서 — 스킬과 넛지

`sync_iris_control`은 MCP 블록 `iris-control`을 Hermes `config.yaml`에 맞추고, `SKILL_NAMES` 10개의 `SKILL.md`가 바이트가 다를 때만 복사한다. 스킬은 모델이 고르는 절차다. 도구 호출을 대신하지 않는다.

`iris-work-start`는 `ide.enter_companion`만으로 폴더가 바뀌지 않는다고 적는다. `project.open_similar` 또는 `ide.open_folder`를 쓰라고 한다. 이 문장이 없으면 카탈로그 한 줄만으로는 컴패니언 타일이 빠진다.

`iris-wiki`는 저장·이동의 `ok` 없이 말했다고 하지 말라고 적는다. 넛지 15번은 같은 금지를 다시 적고, 여러 페이지는 `wiki.import_pages`라고 덧붙인다. 스킬과 넛지가 어긋나면 모델은 둘 중 늦게 읽은 쪽을 따른다. 어느 쪽이 최신인지는 도구가 보장하지 않는다.

`iris-session-status`는 상태 스냅샷만 요약하라 한다. 액션을 나열하지 않는다. 파악의 절반은 `get_state`로 충분하다는 뜻이다.

### 4.3 말과 클릭이 갈라지는 자리

`_execute_user_turn`은 `hermes_owns_local_intents`가 참이면 문장을 `HermesChatWorker`로 보낸다. 클릭 슬롯은 이 함수를 지나지 않는다.

같은 핸들러를 버튼이 직접 부르는 구조라서, 「모든 일이 헤르메스를 탄다」와 「모든 일이 같은 함수로 실행된다」는 다른 문장이다. 지금은 후자만 맞다. 전자로 바꾸면 메일 아이콘이 게이트웨이 왕복을 기다린다. 헤르메스가 꺼지거나 MCP가 끊기면 아이콘도 죽는다. `get_state`의 `hermes_online`이 거짓이어도 창은 떠 있어야 한다.

`invoke`가 UI 스레드로 마샬하는 이유는 위젯 접근이다. 그 자리에 모델 호출을 넣으면 슬롯이 네트워크를 기다리다가 막힌다. Qt 슬롯 밖으로 예외가 나가면 프로세스가 죽는 경로는 이미 따로 있다.

### 4.4 하지 않은 일

- 설정 대화상자가 레지스트리를 통하지 않고 설정 파일을 쓰는지는 03과 같이 이 턴에서 실행해 보지 않았다.
- Hermes가 실제로 켜진 PC에서 스킬 10개가 디스크에 복사돼 있는지는 코드를 읽었고, 현재 홈 디렉터리를 열어 보지 않았다.
- `mobile-mcp` 도구 목록은 아이리스 카탈로그와 별개라 세지 않았다.
- `_check_control_action_split`를 다시 돌리지는 않았다.

## 5. 전부 태울 때의 장단, 그리고 만들어도 되는지

### 5.1 말을 헤르메스에 태우는 쪽 (이미 기본)

장점. 저장·실행·설치를 모델이 도구 결과 없이 말했다고 하기 어렵다. 위험 액션은 `confirm`으로 한곳에서 막힌다. 로컬 정규식과 도구가 따로 노는 일이 줄어든다. 03의 남은 가로채기(확장 설치 대기 답)도 모델이 `extension.install_github`를 다시 부르면 사라진다.

단점. 한 줄 조작도 게이트웨이 왕복이 있다. MCP가 끊기면 말은 아이리스를 못 움직이고, 넛지 19번은 그때 지어내지 말고 끊겼다고 말하라 한다. 설명서가 스킬과 넛지 두 벌이라 한쪽만 고치면 모델이 옛 절차를 탄다.

### 5.2 클릭·창·에디터 키까지 태우는 쪽 (만들지 말 것)

장점이라고 볼 수 있는 것은 감사 로그가 문장으로 남는 것뿐이다. 그건 핸들러 안의 `activity.log`로 충분하다.

단점. 지연. 헤르메스 장애가 창 장애가 된다. 채팅을 보여주는 프로그램이 채팅 모델에게 창 그리기를 맡기는 순환이다. `chat.stop`이나 `chat.new_session`을 진행 중인 턴 안에서 다시 에이전트로 넣으면 재진입한다. 소셜 스텁 4개는 준비 중인데 모델이 열렸다고 말할 수 있다. 15초 타임아웃 안의 UI 마샬에 모델 지연을 더하면 컨트롤 표면이 타임아웃한다.

### 5.3 헤르메스가 아이리스를 제대로 잡고 다루게 하려면

소스 전체를 프롬프트에 넣지 않는다. 잡을 대상은 레지스트리지 파이썬 모듈이 아니다.

1. 목록은 `iris_get_catalog` 하나. 핸들러를 추가하면 `register()` 요약에 **필수 인자 이름**을 적는다. 지금 비어 있는 59개가 스킬 문단 없이 호출되려면 이 한 줄이 인자까지 말해야 한다.
2. 스킬은 순서가 틀리면 사고가 나는 절차만 둔다. 컴패니언으로 폴더 열기, 위키는 도구 `ok` 전에 저장했다고 하지 않기, 이동은 다시 쓰지 않기, 실행은 `project.run`만. 10개를 122개 설명서로 키우지 않는다.
3. MEMORY 넛지는 스킬과 같은 문장을 복제하지 않는 쪽으로 줄인다. 지금은 v19가 마켓플레이스·확장을 알고 스킬 `iris-wiki`는 모른다. 모델은 둘 다 읽는다.
4. 지금 화면은 `iris_get_state`만 믿는다. 위키 목록이 필요하면 `wiki.list_notes`를 부르게 두고, 상태 스냅샷에 금고 전체를 넣지 않는다.
5. 「준비 중」 스텁은 카탈로그에 두더라도 요약이 실패를 말해야 한다. 지금 요약은 화면 이름만 있다.

이 다섯이 「완벽하게 파악」의 상한이다. 그 이상은 아이리스 구현을 모델이 외우는 일이고, 핸들러가 바뀌면 바로 틀린다.

### 5.4 판정

지금의 모양 — 말은 헤르메스, 손은 세 도구, 몸통은 사이드바와 같은 핸들러, 설명서는 짧은 스킬 — 으로 만드는 것이 맞다.

모든 아이리스 작업을 헤르메스 턴으로 보내는 것은 만들지 않는다. 122개 이름을 스킬과 넛지에 전부 베끼는 것도 만들지 않는다. 파악의 빈자리는 카탈로그 요약이 인자를 말하지 않는 것과, 설명서가 두 벌인 것이다.
