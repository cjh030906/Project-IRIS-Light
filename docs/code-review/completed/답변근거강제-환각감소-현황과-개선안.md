# 답변 근거 강제 — 환각·지어냄·거짓보고

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1002-01 |
| 작성일 | 2026-10-02 |
| 대상 | Iris 채팅 답변의 사실 진술과 실행 보고 |
| 목적 | 요청에 따라 검색·RAG 등 근거를 강제하면 환각·지어냄·거짓보고가 줄어드는지, 현재 코드 기준으로 판단 |
| 조사 범위 | 채팅 프롬프트 조립, History·위키 노트 검색, 루틴 웹 검색, 첨부 자료 발췌, 파일 쓰기 완료 게이트, SOUL |
| 하지 않은 일 | 코드 수정, 이번 조사에서의 모델 호출 |

---

## 1. 결론

줄어든다. 매 답에 검색이나 RAG를 붙인다고 없어지지는 않는다.

이 코드에서 이미 줄어든 경우는 둘뿐이다.

- 앱이 자료를 먼저 넣고, 실패하면 실패 사실을 넣은 뒤, 모델은 그 블록만 정리한다. 루틴의 오늘 뉴스, 첨부·경로·URL 발췌가 이 경우다.
- 완료 문장을 도구 `ok`와 디스크 파일로 지운다. 파일 쓰기가 이 경우다.

프롬프트에 “지어내지 마라”, “출처를 밝혀라”만 있는 일반 채팅은 그대로다. 위키 발췌는 붙지만, 답이 그 발췌 안에 있는지는 검사하지 않는다. 웹 검색은 채팅에서 모델이 도구를 부를지에 맡긴다. 도구가 없는 Ollama 직행은 오늘 사실을 지어낸다. `routine_search.py`가 gemma4로 그 증상을 적어 두었다.

근거 강제가 막는 것과 못 막는 것은 다음과 같다.

| 증상 | 근거를 앱이 먼저 넣으면 | 못 막는 이유 |
|---|---|---|
| 오늘 뉴스·시세·날씨를 지어냄 | 줄어든다 | 검색 결과가 틀리거나 비면, 그 빈칸을 모델이 채운다 |
| 저장 자료에 없는 내용을 있다고 함 | 줄어든다 | 발췌를 잘못 읽거나, 관련 없는 노트를 근거로 쓴다 |
| 파일을 만들었다고 함 | 검색·RAG로는 안 줄어든다 | 도구 결과·디스크 대조가 필요하다. 이미 파일 쓰기만 그렇게 한다 |
| 계산·코드·글의 오류 | 거의 안 줄어든다 | 외부 근거가 없는 일이다. 억지 검색은 잡음이 된다 |
| 없는 URL을 출처로 씀 | 검색만으로는 안 줄어든다 | 인용 칩은 모델이 쓴 주소를 그대로 그린다 |

---

## 2. 현재

답은 한 통로가 아니다. 근거가 붙는 방식은 요청 종류마다 다르다.

| 경로 | 앱이 하는 일 | 답이 근거에 묶이는가 |
|---|---|---|
| 일반 채팅 (Hermes) | 시스템 문장으로 도구 사용·출처 절을 요구. SOUL은 “모르는 척하지 마라”, “안 한 일을 했다고 하지 마라” | 아니다. 모델이 도구를 안 불러도 답이 나간다. 호출 결과는 문장으로만 남는다 |
| 일반 채팅 (Ollama 직행) | 도구 없음. SOUL 원문을 시스템으로 넣음 | 아니다. 오늘 사실은 가중치로 쓴다 |
| 위키 노트 | 4자 이상이면 저장 노트를 FTS+임베딩으로 최대 3건, 발췌 상한 약 2,400자. “발췌에 있는 문장만 저장된 사실”이라고 적음 | 반쪽. 검색이 비면 이 문장 자체가 안 들어간다. 나온 답이 발췌와 맞는지는 안 본다 |
| 이전 대화 | 설정이 켜져 있고 유사도가 충분할 때만 최대 3건. “관련 있을 때만, 이전 대화에서라고 밝혀라” | 아니다. 참고용이다. 옛 답이 틀려도 다시 근거가 된다 |
| 모델 전환 인수인계 | History 발췌를 참고 근거로 얹음 | 아니다. 전환용이다 |
| 예약 루틴 | 검색어가 있으면 SerpAPI를 앱이 먼저 호출. 실패 문구를 넣고 “지어내지 마라”. 지식만 필요한 일은 검색어를 비움 | 지시에 가깝다. 그래도 정리문이 검색 결과 밖인지는 안 자른다 |
| 첨부·`@경로`·URL | 모델 전에 발췌. 실패 이유만 있으면 그 이유만 말하라 | 지시에 가깝다. 발췌 밖 문장을 지우지는 않는다 |
| 파일 쓰기 | “처리 완료” 등 특정 문장은 `project.write_file` ok와 파일 실재가 있을 때만 남김 | 그렇다. 그 문구 밖 거짓 보고는 남는다 |
| 인용 표시 | 본문의 URL을 칩으로 그림 | 아니다. 이번 턴 검색 결과와 대조하지 않는다 |

관련 코드: `iris/ui/window/main_window.py`의 `_with_past_chats`, `_chat_messages_with_project_context`, `_routine_evidence`. `iris/knowledge/wiki_note_index.py`의 `wiki_prompt_for_query`(빈 결과면 빈 문자열). `iris/runtime/routine_search.py`. `iris/knowledge/material_excerpt.py`. `iris/ui/chat/file_write_claim.py`. `iris/core/chat_citations.py`. `integrations/hermes-soul/SOUL.md`.

SOUL은 사실 구분을 요구하면서, 정보가 부족해도 가정을 세워 진행하라고 한다. 엄격한 근거 강제와 같은 방향이 아니다.

## 3. 목표

환각을 0으로 만드는 것이 목표가 아니다. 아래 네 종류만 근거 밖으로 나가지 않게 하는 것이다.

1. **오늘 사실.** 뉴스·날씨·시세·경기 결과. 앱이 검색한 결과만 말하고, 검색 실패면 실패만 말한다.
2. **저장된 자료·첨부.** 위키 노트와 이번 턴에 읽은 파일·URL. 발췌에 없으면 없다고 한다. 일반 지식으로 메우지 않는다.
3. **실행 보고.** 파일 쓰기, 위키 저장, 검색, 메일 전송, 코드 실행. 이번 턴 도구 ok가 있을 때만 “했다”고 한다.
4. **그 외.** 글쓰기, 계산, 코드 설계, 의견. 검색·RAG를 강제하지 않는다.

이전 대화 기록은 2번의 근거로 올리지 않는다.

---

## 4. 개선안

새 검색 엔진이나 에이전트 프레임워크는 넣지 않는다. 이미 있는 두 방식만 일반 채팅에 넓힌다.

1. **질문 종류는 앱이 가른다.** 오늘 사실 / 저장·첨부 / 실행 / 그 외. 모델에게 “필요하면 검색하라”고 맡기지 않는다. 루틴이 검색어를 명시하는 이유와 같다.
2. **오늘 사실은 루틴과 같은 검색을 채팅에도 쓴다.** `run_search` → `format_evidence`. 키가 없거나 결과가 없으면 그 문장만 답으로 하고 모델 호출을 하지 않거나, 실패 블록만 넣는다. Hermes 도구 호출에 맡기면 직행 경로와 미호출이 남는다.
3. **위키·첨부는 빈 결과를 숨기지 않는다.** 지금 `format_note_prompt`는 0건이면 빈 문자열이라, “없으면 없다고 해라”가 전달되지 않는다. 저장 자료를 묻는 질문에서 0건이면 그 사실을 블록으로 넣는다. 발췌가 있으면 답은 그 발췌의 문장으로 제한한다고 같은 블록에 적되, 최종 문장이 발췌에 없는 고유명·숫자를 말하면 그 문장만 빼고 “발췌에 없다”를 남긴다. 모든 문장 일치는 하지 않는다. 고유명과 숫자만 대조한다.
4. **실행 보고는 문구 목록을 늘리지 않는다.** 파일 쓰기 게이트는 “처리 완료” 등 네 표현만 본다. 같은 방식의 금지어를 늘리면 다른 말투가 통과한다. 이번 턴에 성공한 도구가 없으면 “했다·완료·저장했다·검색했다·보냈다·실행했다” 류 문장을 도구 이름과 ok 결과 한 줄로 바꾼다.
5. **인용 URL은 이번 턴 검색·발췌에 있는 주소만 칩으로 남긴다.** 없는 주소는 본문에서 뺀다.
6. **이전 대화는 지금 헤더를 유지한다.** 사실 근거로 격상하지 않는다. 옛 환각이 다음 답의 근거가 된다.
7. **볼 숫자만 남긴다.** 검색 실패 뒤 본문이 길다 / 도구 ok 없이 완료 문장이 남았다 / 인용 URL이 이번 턴 결과에 없다. 이 세 건의 횟수.

하지 말 것: 모든 턴에 웹 검색, 위키 전문을 매 턴 투입, 프롬프트 문장만 늘리기, 이전 대화 답을 검증된 사실로 취급, Instructor·별도 검증 모델 추가.
