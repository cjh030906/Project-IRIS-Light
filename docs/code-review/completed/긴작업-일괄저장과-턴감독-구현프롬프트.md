# Prompt: 긴 작업 — 일괄 저장 + 턴 감독

아래 블록을 Cursor Agent에 그대로 붙여 넣으면 됩니다.

배경: `https://rl.ai.jiny.dev/` 전체 저장 시험. Gemma는 저장한다고 말하고 턴을 닫았고, 로그의 위키 성공은 수 건이었다. Hermes가 중간에 자른 것이 아니다. 모델이 최종 문장을 내면 그 HTTP 스트림의 도구 반복이 끝난다. Iris는 그 문장을 완료로 기록한다. 반복 횟수 상한이나 스킬 문장만으로는 이번 증상이 안 줄어든다.

---

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- 증상: "사이트 전부를 위키에 저장" 같은 요청에서 모델이 도구를 몇 번 부른 뒤
  "이어서 진행하겠다 / 계속할까요"로 턴을 끝낸다. 사용자는 그 문장을 완료로 본다.
- 원인:
  - wiki.import_content / wiki.write_user_note 는 소스 1건이다.
    67페이지는 모델이 도구를 67번 불러야 하고, 호출 사이에 턴을 닫을 수 있다.
  - Hermes 한 요청 안의 도구 루프는 모델의 최종 문장에서 끝난다.
  - _on_chat_finished 는 그 문장을 히스토리에 넣고 턴을 닫는다.
    남은 페이지 수나 "이어서" 문장을 보지 않는다.
  - 도구 성공은 진행 문자열로만 온다. 예: "Iris control: wiki.write_user_note ok".
    "[Hermes tool] completed" 는 성공이 아니다.
- 이미 있는 것. 건드리지 말 것:
  - _gate_chat_completion / file_write_claim : 코드 펜스 저장 주장 검사. 이번 감독과 합치지 말 것.
  - explain_chat_error : 채팅 실패 안내. 429에서 자동 재시도를 붙이지 말 것.
  - import_to_wiki (iris/knowledge/wiki_import_ops.py) : 노트 1건 저장. 페이지 루프는 이 함수를 재사용.

Goal:
두 겹만 구현한다.
1) 목록이 있는 위키 저장은 Iris가 한 번에 처리한다. 모델은 도구를 한 번 부른다.
2) 그 밖 긴 요청은, 모델이 "이어서 하겠다"로 닫고 목표가 남아 있으면
   사용자 입력 없이 상한 안에서 다음 턴을 넣는다.
모델이 "완료"라고 말한 것을 완료로 보지 않는다. 완료는 도구 결과와 위 규칙이다.

Constraints:
- YAGNI: 아래 Interface 밖 금지. 범용 크롤러, 사이트맵 추측, Hermes max iteration 변경, 스킬 문장만으로 끝내기 금지.
- Surgical: 지정 파일과 새 모듈·그 자체 검사만. 무관 리팩터 금지.
- 새 의존성 금지. 표준 라이브러리 HTML 파서(html.parser)와 기존 import_to_wiki 만.
- 자동 다음 턴은 채팅 실패(429 포함), 사용자가 멈춤, 대화 전환에서는 돌지 않는다.
- 자동 턴은 음성 따라하기(_finish_current_turn open_followup)를 열지 않는다.
- API 키·페이지 본문 원문을 진행 로그에 남기지 말 것. 건수와 주소·상대 경로만.
- 콘솔 창 금지.

Interface (구현 계약):

1) 일괄 저장 `wiki.import_pages`
   등록: iris/ui/control_actions/wiki.py. 기존 wiki.import_content 는 그대로 둔다.
   인자:
   - sources: URL 또는 파일 경로 배열. 또는 source 하나(문자열).
   - discover: true 이면 source(첫 URL)와 같은 호스트의 a[href] 를 한 단계만 모아 sources 에 합친다.
     html/htm 과 확장자 없는 문서 링크만. 이미지·pdf·zip·메일·javascript: 는 제외.
     다른 호스트, 조각(#)만 다른 중복은 제외. 깊이 2 이상 금지.
   - mode: raw | summarize. 기본 raw. summarize 는 기존 wiki_import_content 와 같은 모델 조건.
   - limit: 기본 80, 최대 80. 넘는 후보는 자르고 truncated=true.
   동작:
   - 각 소스는 import_to_wiki 한 번. 노트마다 위키 화면을 열지 말 것.
   - 한 건 실패는 다음 건을 막지 않는다.
   - 끝난 뒤 위키 화면을 한 번만 열고 그래프를 갱신한다. 마지막 성공 노트만 연다. 성공이 없으면 열지 않는다.
   반환 ok:
   - saved, failed, truncated, items[{source, ok, rel_path|error}]
   빈 sources 는 err.

2) 링크 수집은 iris/knowledge/wiki_import_ops.py 의 순수 함수
   collect_same_origin_links(page_url: str, html: str, *, limit: int) -> list[str]
   네트워크는 액션 쪽에서만. 함수 자체 검사로 호스트·확장자·상한·중복을 고정한다.

3) 턴 감독 순수 함수. 새 파일 iris/runtime/turn_followthrough.py
   decide_followthrough(goal: str, assistant: str, tool_ok_count: int, followups: int, *, cap: int = 8) -> str
   반환은 "continue" | "stop" | "ask" 만.
   - followups >= cap → stop
   - 채팅 실패 경로는 이 함수를 호출하지 않는다.
   - continue: 사용자 목표에 저장·수집·전부·모든·하나하나·순차·페이지 가 있고,
     assistant 가 이어서 하겠다는 말(계속, 이어서, 다음 장, 넘어가, 진행하겠, 저장하겠, 시작하겠, 계속할까요, 진행할까요)로 끝나며,
     이번 턴 tool_ok_count 가 목표 건수를 채웠다는 증거가 없다.
     "계속할까요"는 사용자가 이미 전부 저장·계속을 말한 목표에서는 ask 가 아니라 continue 다.
   - ask: 목표에 없는 선택(어느 쪽, 어떤 파일, 삭제할까, A 또는 B)만 물을 때.
   - stop: 그 외. 도구 성공이 있고 이어서 하겠다는 말이 없으면 stop.
   - tool_ok_count==0 이고 목표가 위키 저장·가져오기인데 assistant 가 저장 완료만 말하면 continue.
     완료 문장을 믿지 않는다.
   자체 검사에 이번 시험 문장을 넣는다.
   - goal "웹사이트 모든 내용을 위키에 저장", assistant "1강을 저장했습니다. 계속할까요?", tool_ok_count 2 → continue
   - 같은 goal, assistant "67건 저장, 0건 실패", tool_ok_count 1 → stop
     (일괄 도구가 숫자를 반환한 답은 이어서 돌리지 않는다. "N건 저장" 과 "실패" 가 같이 있으면 stop)
   - goal "오늘 날씨 알려줘", assistant "서울은 맑습니다.", tool_ok_count 0 → stop
   - goal "위키에 저장", assistant "어느 파일로 저장할까요?", tool_ok_count 0 → ask
   - followups==8 → stop

4) 메인 창 연결 (iris/ui/window/main_window.py)
   - 턴 시작 시 tool_ok_count=0. _on_hermes_tool_progress 에서
     문자열이 " ok" 로 끝나거나 " ok " 를 포함하면(예: "wiki.write_user_note ok") 1 증가.
     "completed" / "running" 은 증가시키지 말 것.
   - 사용자가 직접 보낸 새 메시지면 followups=0, goal=그 메시지.
     자동 턴이 이어지는 동안 goal 은 처음 사용자 메시지를 유지한다.
   - _on_chat_finished 에서 히스토리 기록 후 decide_followthrough.
     continue 이면 채팅에 노트 한 줄 "남은 작업이 있어 이어서 진행합니다." 만 보이고,
     모델에게는 사용자 발화로 다음 한 줄을 보낸다.
     "이미 요청된 작업을 멈추지 마라. 완료라고 말하지 말고 이번 턴에 도구를 호출하라.
      사이트 전체 저장이면 wiki.import_pages 한 번이면 된다."
     이 발화는 음성 입력으로 처리하지 않는다. 기존 채팅 전송 경로로 다음 턴을 연다.
     open_followup 은 False.
   - ask 또는 stop 이면 자동 턴을 만들지 않는다.
   - cap 에 걸린 stop 이고 followups>=cap 이면 노트 한 줄:
     "자동 진행 상한에 도달했습니다. 이어서 하려면 다시 요청하세요."
   - _on_chat_failed, 멈춤, 대화 전환 시 followups 와 예약 자동 턴을 버린다.

5) 모델이 일괄 도구를 알게 할 문구. 짧게.
   - iris/system/hermes_memory_nudge.py 15번과
     main_window 의 위키 저장 시스템 문장에 한 줄:
     여러 페이지·사이트 전체는 wiki.import_pages (source 또는 sources, discover=true).
     페이지마다 import_content 를 반복하지 말 것.
   - 저장 성공은 반환의 saved 건수로만 말한다.

6) 테스트
   - collect_same_origin_links: 같은 호스트 2개, 다른 호스트 1개 제외, png 제외, limit 적용.
   - decide_followthrough: Interface 3의 다섯 경우.
   - import_pages 는 임시 파일 2개를 sources 로 넣어 saved==2. 네트워크 없는 검사.
     discover 의 HTTP 는 이 검사에 넣지 말 것.
   - 실행:
     .venv\Scripts\python.exe -m iris.runtime.turn_followthrough
     .venv\Scripts\python.exe -m iris.knowledge.wiki_import_ops
     (wiki 액션 자체 검사가 이미 있으면 그 모듈도)

Implementation order:
  Phase A: collect_same_origin_links + decide_followthrough + 자체 검사
  Phase B: wiki.import_pages 가 import_to_wiki 를 루프. UI는 마지막에 한 번
  Phase C: 메인 창 카운트·자동 턴·실패/멈춤 시 취소
  Phase D: nudge 와 시스템 문장 한 줄
  Phase E: 이 문서 상태 표를 완료로 고치고 한국어로 요약

Output:
- 위 범위 diff만
- 자체 검사 초록
- 짧은 한국어: 일괄 도구가 몇 건을 한 번에 쓰는지 / 어떤 문장이 자동 다음 턴인지 / 429와 사용자 멈춤은 왜 자동 진행이 아닌지

Do not:
- Hermes 반복 횟수, SOUL, 스킬 본문으로 모델이 스스로 끝까지 가게 만들기
- 모델의 "저장했습니다" 문장을 완료 증거로 쓰기
- discover 를 2홉 이상 재귀 크롤로 만들기
- limit 80 을 넘기기
- 자동 턴마다 TTS로 긴 완료 인사를 다시 읽기. 노트 한 줄이면 된다
- _gate_chat_completion 을 이 감독에 합치기
- 채팅 실패 시 같은 모델을 자동 재호출하기
```
