# 위키 폴더 이동 — 「어느 노트인지 알 수 없습니다」

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1003-01 |
| 작성일 | 2026-10-03 |
| 대상 | 「학습자료 아래 강화학습(영어) 폴더를 만들고 챕터 폴더를 통째로 옮겨 달라. 먼저 그 내용들을 삭제해 달라」 |
| 목적 | 답이 `위키 처리 실패: 어느 노트인지 알 수 없습니다. 경로를 알려 주세요.` 로 끝난 이유 |
| 조사 범위 | 채팅 턴 분기, `parse_wiki_command`, `execute_wiki_command`, 삭제·이동 도구 |
| 하지 않은 일 | 코드 수정, 위키 파일 삭제·이동 |

관련 이전 기록: `docs/code-review/위키-inbox분류-원본유지-원인.md` (2026-10-02). 그때는 모델이 새 파일을 쓰고 inbox는 그대로 두었다. 이번은 모델 턴까지 가지 않는다.

---

## 1. 결론

요청 문장에 「위키」와 「삭제」가 같이 있다. 로컬 파서는 그 두 단어만 보고 **노트 하나 삭제**로 확정하고, 채팅 턴을 거기서 끝낸다. 폴더를 만들고 챕터를 옮기는 뒷문장은 읽지 않는다. Hermes에도 넘기지 않는다.

삭제 명령에는 경로와 제목이 둘 다 비어 있다. 실행부가 노트 하나를 고르다 실패하고, 그 예외 문장이 그대로 채팅에 붙는다.

같은 문장을 `parse_wiki_command`에 넣으면 결과는 `WikiCommand(op='delete', rel_path='', title='')` 이다. 사용자가 본 문장과 같다.

---

## 2. 구조

```
사용자 문장
  「위키에서 … 내용들을 삭제해주고, … 영어 제목 폴더를 만들어 … 챕터폴더들을 통째로 옮겨줘」
        │
        ▼
_execute_user_turn
  try_wiki_command 가 명령을 만들면 즉시 return
  Hermes·도구 루프는 이 턴에 열리지 않음          ← 이번 갈림
        │
        ▼
parse_wiki_command
  맨 앞 조건: 「삭제」+「위키」
  op=delete, rel_path=_wiki_last_rel, title=따옴표 안 제목
  이번: 직전 노트 경로 없음, 따옴표 없음 → 둘 다 빈 문자열
  폴더 만들기·챕터 이동은 이 함수에 분기가 없음
        │
        ▼
execute_wiki_command  op=delete
  _resolve
    rel_path 없음, title 없음
    ValueError「어느 노트인지 알 수 없습니다. 경로를 알려 주세요.」
        │
        ▼
wiki_turn._fail
  채팅: 「위키 처리 실패: 」+ 예외 문자열
  디스크 변경 없음
```

원하는 배치 `학습자료 / <강화학습 영어 이름> / 챕터 / 노트` 로 가는 간선은 이 경로에 없다. 삭제도 파일 하나(`delete_user_note` → `Path.unlink`)뿐이고, 폴더 단위는 없다.

---

## 3. 확인한 사실

사용자 문장 재현 (`parse_wiki_command`, 대상 경로 없음):

- `op=delete`
- `rel_path=""`
- `title=""`

대상 경로를 `user/inbox/x.md`처럼 넣어 보면 같은 문장이 그 **한 파일** 삭제로 바뀐다. 챕터 묶음은 여전히 안 된다. 이번 답은 「노트가 여러 개입니다」가 아니라 빈 힌트 분기이므로, 당시 `_wiki_last_rel`도 비어 있었다.

`action_catalog.json`의 위키 액션은 `list_notes`, `open_note`, `reload`, `search`, `write_user_note`, `import_content`, `import_pages` 뿐이다. `delete_note` 핸들러는 `iris/ui/control_actions/wiki.py`에 있으나 카탈로그에 없고, 폴더 이동·이름 변경 액션은 카탈로그와 `execute_wiki_command` 양쪽에 없다. 이번 턴은 그 도구까지 도달하지 않았다.

---

## 4. 코드 리뷰

### 4.1 턴이 로컬 삭제에서 끊긴다

`iris/ui/window/main_window.py` `_execute_user_turn`은 Hermes보다 먼저 `try_wiki_command`를 호출한다. 명령이 있으면 `return`이라 모델이 폴더 구조를 볼 기회가 없다.

`iris/ui/wiki_turn.py` `try_wiki_command`는 파서 결과만 받고 `_start`로 실행한다. 삭제는 `needs_model()`이 거짓이라 워커 없이 `execute_wiki_command`를 바로 호출한다. 예외는 `_fail`이 `위키 처리 실패: {err}`로 붙인다.

### 4.2 파서는 「삭제해줘」만 본다

`iris/knowledge/wiki_command.py`

- `_wants_delete`: 문장에 `삭제`·`지워`·`없애`·`delete`가 있으면 참. 「없애지/지우지/삭제하지」만 예외.
- `_delete_context`: `위키`·`노트`·`문서`·`wiki` 중 하나면 참. 폴더·챕터·여러 파일은 보지 않는다.
- `parse_wiki_command` 184행: 위 둘이면 즉시 `WikiCommand(op="delete")`를 반환한다. `rel_path`는 인자 `target`(화면의 `_wiki_last_rel`), `title`은 `_quoted`(큰따옴표·작은따옴표·「」). 이번 문장에는 둘 다 없다.
- 그 아래 `list` / `open` / `create` / `save` / `update` / `reprocess`는 실행되지 않는다. 「폴더를 만들어」「통째로 옮겨」에 해당하는 op는 함수 안에 없다. `create`는 「새 노트」처럼 노트 한 장을 만들 때만 탄다.

### 4.3 실행은 노트 하나를 요구한다

`iris/knowledge/wiki_ops.py` `_resolve`: `rel_path`가 있으면 그걸 쓰고, 없으면 `title`로 `match_wiki_notes`를 돌린다. 제목이 비면 98행에서 이번 오류를 낸다. 후보가 없으면 110행에서 같은 문장을 낸다. 여러 개면 「노트가 여러 개입니다」.

`delete` 분기(315행)는 `_resolve`가 돌려준 경로 하나만 `IrisWiki.delete_user_note`에 넘긴다. `iris/knowledge/iris_wiki.py` `delete_user_note`는 그 경로가 파일이면 `unlink`한다. 디렉터리를 지우거나 옮기지 않는다.

### 4.4 하지 않은 일

- 위키 트리 UI는 이번 실패에서 호출되지 않았다.
- 분류기(`wiki_filing`, `classify_note`)는 이번 턴에 안 탄다.
- 완료 게이트·턴 감독은 모델 답변을 검사하지 않았다. 답이 예외 문자열이라 그 단계까지 가지 않는다.

---

## 5. 빈 자리

구조에서 비어 있는 것은 다음뿐이다.

1. 문장 앞의 「삭제」가 폴더·여러 노트를 지우는 명령으로 바뀌지 않는다. 노트 경로 하나가 없으면 실패로 끝난다.
2. `학습자료` 아래에 영어 이름 폴더를 만들고, 그 아래 기존 챕터 폴더를 통째로 옮기는 op가 `parse_wiki_command`와 `execute_wiki_command`에 없다.
3. 로컬 파서가 명령을 만들면 모델 도구(`wiki.write_user_note` 등)로 내려가지 않는다. 카탈로그에도 폴더 이동은 없다.
