# Prompt: 채팅 제목 — 질문 전문을 쓰지 않기

배경: `docs/code-review/채팅제목-질문전문-원인과-코드리뷰.md` (IRIS-REV-2026-1003-01).
제목 저장은 연결되어 있다. 다만 `suggest_title`이 사용자 문장에서 조사만 뺀 토큰을 쓰고, 설정 문구와 `summarize_reply`가 말하는 답변 첫 문장은 기록되지 않는다. `_maybe_refresh_title`은 그 함수가 고른 주제보다 갱신 조건이 좁다. 채팅 HTML은 `script`/`style`/`iframe`만 지운다.

이 프롬프트는 그 보고서 5번의 빈 자리와 4.2의 HTML·주소 구멍을 한 계약으로 고정한다. 새 요약 모델은 두지 않는다.

---

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6 / SQLite)
- 기본 기준 chat_title_basis = last
- 지금 last/first 모두 사용자 토큰(summarize_work_title)만 제목으로 쓴다.
- summarize_reply 는 답변 첫 문장을 36자로 자르지만, 스키마가 중단 안내문 제목을 되돌릴 때만 호출된다.
- 질문에서 조사만 뺀 25자 문자열도 제목으로 통과한다.
- 제목이 한 번 생기면 last 여도 첫 주제와 마지막 사용자 문장이 멀 때만 다시 쓴다.
- InterruptedTitleTests 는 답변 첫 문장·중단 안내문이면 「새 채팅」을 기대하고 실패한다.
- test_chat_conversations.py 와 _check_chat_sessions.py 는 사용자 토큰 제목을 기대한다.
- _sanitize_chat_html 은 script/style/iframe 만 제거한다. img 주소 스킴을 거절하지 않는다.
- ChatSession.record 는 DB 실패 시 메모리 history 를 그대로 둔다.

Goal:
제목 계약을 하나로 맞춘다.
- last: 마지막 실질 아이리스 답변의 첫 문장. 사용자 문장은 제목이 되지 않는다.
- first: 첫 질문의 작업 제목. 조사만 뺀 질문이면 거절하고, 그 질문에 대한 첫 실질 답변의 첫 문장을 쓴다.
중단 안내문만 있는 답변은 제목 재료가 아니다. 앞에 실질 답변이 있으면 그 문장을 유지한다.
잠긴 제목은 자동으로 바꾸지 않는다.
채팅 HTML 은 허용 태그만 남기고, javascript/data/vbscript/file 주소를 받지 않는다.
DB에 못 쓴 메시지는 다음 턴 history 에 남기지 않는다.

Constraints:
- LLM 제목 호출, 새 의존성, 기존 대화 제목 일괄 재작성 금지.
- 사이드바는 DB title 을 그대로 표시한다. 표시층에서 다시 요약하지 않는다.
- SQL 바인딩과 제목 잠금(rename_conversation)은 유지한다.
- 대화 본문을 다음 요청에서 빼지 않는다. 채팅은 이전 턴을 다시 보낸다.
- Qt 슬롯 밖으로 예외를 보내지 않는다.
- 코드 카드·파일 칩·https 링크·표·iris-* 앵커는 그대로 보여야 한다.

Interface:

1) 제목 (iris/storage/conversations.py)
   suggest_title(messages, *, basis=last) -> str
   - last: 비서 본문에서 INTERRUPTED_NOTE 를 뺀 뒤, 비지 않은 마지막 본문의 summarize_reply.
     실질 답변이 없으면 DEFAULT_TITLE. 사용자 문장으로 채우지 않는다.
   - first: 사용자 본문에서 [첨부 파일], [자료 본문], @"경로" 뒤를 잘라 낸 첫 주제의 summarize_work_title.
     제목 토큰이 모두 원문에 있고, 두 단어를 넘겨 질문의 조사만 뺀 것이면 거절한다.
     새 단어가 있거나 두 단어 이하로 줄인 핵심은 유지한다. (예: 「IRIS 구조」, 「PDF 저장 종료 오류 수정」)
     거절하거나 빈 문자열이면, 그 질문 다음 첫 실질 답변의 summarize_reply.
   _maybe_refresh_title
   - 제안이 비거나 「새 채팅」이거나 기존과 같으면 쓰지 않는다.
   - first 이고 이미 제목이 있으면 쓰지 않는다.
   - last 이고 제안이 다르면 쓴다. topic_shifted 로 한 번 더 거르지 않는다.
   refresh_conversation_title 은 잠기지 않은 제목에 suggest_title 결과를 그대로 쓴다.

2) 설정 문구 (iris/ui/settings/hud_dialog.py build_chat_title_box)
   마지막 대화 = 최근 답변의 첫 문장.
   첫 대화 = 첫 질문의 짧은 작업 제목. 질문에서 조사만 뺀 경우는 그 질문의 첫 답변 첫 문장.
   직접 고친 제목은 바뀌지 않음.

3) 채팅 HTML (iris/ui/chat/chat_renderer.py)
   _sanitize_chat_html
   - script/style/iframe/object/embed/svg/math/form 은 내용까지 제거.
   - 허용 태그 외 태그는 제거(글자는 유지).
   - on* 속성 제거.
   - href/src 는 http(s), iris-file/wiki/copy/collapse/tts/error/update/hermes-update/stt/diagram/ollama-login, iris-image:, 스킴 없는 상대 경로, 드라이브 경로만.
   - javascript, vbscript, data, file 스킴은 속성에서 뺀다.
   _style_img_tag 는 같은 규칙으로 거절된 src 를 그리지 않는다.

4) 저장 실패 (iris/runtime/chat_session.py ChatSession.record)
   append_message 가 예외면 history 에 넣은 마지막 항목을 빼고 오류 문자열을 반환한다.

5) 테스트
   InterruptedTitleTests 는 고치지 않고 통과해야 한다.
   test_chat_conversations.py 와 iris/ui/_check_chat_sessions.py 의 제목 기대는 위 계약으로 고친다.
   추가: last 는 질문 전문이 아니라 최신 답변 문장. 후속 답이 오면 주제 이동 여부와 상관없이 그 문장으로 바뀐다.
   first 에서 조사만 뺀 질문은 답변 문장으로 간다. 첨부 경로와 「첨부」는 제목에 없다.
   chat_renderer 자검에 script 제거, javascript 링크·이미지 거절, https 링크 유지를 넣는다.

Output:
- 위 파일만 수정한다. 저장된 iris_light.db 제목은 일괄 변경하지 않는다.
- 다음 답변이 저장되거나 설정에서 기준을 다시 저장할 때 새 계약이 적용된다.
```
