## 1. 결론

기능은 구현되어 있고, 저장 경로에도 연결되어 있다. 최근 대화 5개 중 4개의 `title`은 지금 코드의 `suggest_title(..., basis="last")` 결과와 같다. 설정값 `chat_title_basis`도 `last`이다.

보이는 문장은 아이리스 답변도, 별도 요약문도 아니다. 마지막 사용자 문장에서 조사와 요청어를 뺀 단어를 최대 25자까지 이어 붙인 것이다. 그래서 목록에는 질문 그대로로 보인다.

설정 화면 문구와 `summarize_reply`는 다른 계약을 말한다. 「답변 첫 문장을 요약한다」는 경로는 제목 기록에 연결되어 있지 않다. `summarize_reply`는 스키마 정리에서 중단 안내문 제목을 되돌릴 때만 호출된다.

충돌은 세 계약이 한 함수를 두고 갈라진 것이다.

| 계약 | 말하는 내용 | 실제로 제목을 쓰는가 |
|---|---|---|
| 설정 문구 (`build_chat_title_box`) | 사용자 문장이 아니라 아이리스 답변의 첫 문장. 마지막은 최근 답변, 첫 대화는 첫 답변 | 아니오 |
| `suggest_title` + `summarize_work_title` | 사용자 문장의 토큰. `last`는 주제가 바뀐 마지막 질문, `first`는 첫 질문 | 예. DB에 이 값이 있다 |
| `tests/test_past_chats.py` `InterruptedTitleTests` | 답변 첫 문장. 중단 안내문만 있으면 `새 채팅` | 아니오. 이 네 테스트는 실패한다 |

`tests/test_chat_conversations.py`의 제목 테스트는 토큰 제목 계약과 맞아서 통과한다.

## 3. 구조

```
전송
└─ MainWindow._record_history
   └─ ChatSession.record
      └─ append_message
         ├─ chat_messages INSERT
         └─ _maybe_refresh_title
            ├─ 비서 행이 없으면 중단 (사용자만 있으면 제목은 「새 채팅」)
            ├─ load_title_basis  → chat_title_basis (지금 last)
            ├─ suggest_title
            │  ├─ _user_lines          사용자 행만. 비서 본문은 안 읽음
            │  ├─ topic_shifted        last일 때 마지막 주제로 시작점 이동
            │  └─ summarize_work_title 조사·요청어를 지우고 토큰을 이어 붙임
            ├─ 제안이 비거나 「새 채팅」이거나 기존과 같으면 기록 안 함
            ├─ 기존 제목이 「새 채팅」이면 기록
            └─ 이미 제목이 있으면
               topic_shifted(첫 주제, 마지막 사용자 문장)일 때만 기록
         └─ commit
      └─ _refresh_chat_history_panel
         └─ ChatHistoryPanel._ChatRow
            └─ 버튼 = title[:22]+… (24자 초과), 툴팁 = title 전체

설정 저장
└─ SettingsDialog._persist_chat_title_basis
   └─ refresh_conversation_title
      └─ suggest_title (같은 사용자 토큰 경로). 잠긴 제목은 건너뜀

쓰이지 않는 옆 경로
└─ summarize_reply
   └─ 답변에서 코드펜스·도구 표식을 빼고 첫 문장을 36자로 자름
   └─ 호출처는 ensure_chat_schema 한 곳
      (title이 중단 안내문 요약과 같으면 「새 채팅」으로 되돌림)
```

이번 증상이 갈라지는 곳은 `suggest_title`이다. 설정과 `summarize_reply`는 비서 답변을 제목 재료로 둔다. 기록은 사용자 토큰만 쓴다. 그 토큰 정리가 질문과 다른 문장을 만들지 못하면, 질문이 제목이 된다.

id 10이 어긋나는 곳은 그 다음 `_maybe_refresh_title`이다. `suggest_title(last)`는 주제 이동을 차례로 따라가 마지막 주제를 고른다. 저장 조건은 첫 주제와 마지막 사용자 문장만 비교한다. 중간에 바뀐 제목이, 마지막 문장이 첫 주제와 멀리 떨어지지 않으면 그대로 남는다.

## 4. 코드 리뷰

### 4.1 제목

`title_from_text` (`iris/storage/conversations.py`)  
공백을 접고 36자에서 자른다. 요약이 아니다. 제목 기록 경로에서는 `summarize_reply`를 통해서만 쓰이고, 그 함수는 제목을 만들지 않는다.

`summarize_reply`  
답변 첫 문장을 36자로 자른다. 코드 펜스와 `IRIS_TOOL_*` 표식은 뺀다. 설정 문구가 설명하는 동작에 가깝다. 대화가 늘 때 호출되지 않는다. 중단 안내문이 예전에 제목으로 붙은 행을 스키마 초기화에서 되돌리는 데만 쓴다.

`summarize_work_title`  
사용자 문장을 「대상 + 작업」으로 줄이려 한다. 동사 목록과 조사 정규식, 불용어로 토큰을 고르고, 내용 토큰이 2개 미만이면 빈 문자열을 반환한다. 줄이는 데 실패해도 사용자 단어를 반환한다. id 12·15·9가 이 경우다. 빈 문자열일 때만 `suggest_title`이 `새 채팅`으로 떨어진다. 질문과 같아 보이는 제목을 거절하는 조건은 `title == raw` 한 가지뿐이고, 조사만 빠져도 통과한다.

`suggest_title`  
`basis`가 `first`가 아니면 `topic_shifted`로 시작 질문을 뒤로 민다. 그다음 `_anchor_line`과 `summarize_work_title`만 호출한다. 비서 행은 `_user_lines`에서 버려진다. `InterruptedTitleTests`가 기대하는 답변 문장은 이 함수 안에 없다.

`topic_shifted`  
두 문장의 토큰 겹침으로 주제 전환을 본다. 주석대로 어휘 규칙이다. 짧은 후속(「그럼」, 「더 자세히」)은 전환으로 안 본다. `test_title_stays_blank_until_reply_then_summarizes`의 「그럼 그 부분 더 자세히」가 이 경우라 제목이 유지된다. 반대로 id 9처럼 새 명사가 많으면 마지막 질문이 제목이 된다. 첫 질문 요약이라는 기대와 여기서 갈라진다.

`_maybe_refresh_title`  
비서 행이 생기기 전에는 제목을 안 바꾼다. 그래서 질문만 있는 동안은 `새 채팅`이다. 비서 행이 중단 안내문이어도 내용이 있으면 갱신을 시도한다. 안내문 자체는 제목이 되지 않지만, 그 직전에 저장된 사용자 문장으로 제목이 생긴다. `test_title_in_the_real_database_after_a_switch`는 이때 `새 채팅`을 기대하고 실패한다. 이미 제목이 있을 때의 갱신 조건은 `suggest_title`의 마지막 주제와 다르다. id 10이 이 틈에 남아 있다.

`refresh_conversation_title`  
설정에서 기준을 바꿀 때 잠기지 않은 대화를 다시 맞춘다. 좁은 갱신 조건을 쓰지 않고 `suggest_title` 결과를 바로 쓴다. 평소 턴 저장과는 다른 문이다.

`rename_conversation`  
사용자가 고친 제목은 `title_locked = 1`이라 이후 자동 갱신이 없다. 상한 48자. 최근 DB에는 잠긴 제목이 없다.

`append_message`  
user/assistant이고 본문이 있으면 `_maybe_refresh_title`을 호출한 뒤 커밋한다. 제목 UPDATE와 메시지 INSERT는 같은 커밋이다.

`build_chat_title_box` (`iris/ui/settings/hud_dialog.py`)  
안내 문장이 구현과 반대다. 「사용자 문장이 아니라 답변 첫 문장」이라고 적혀 있다. 콤보 값 `last` / `first`는 답변 시점이 아니라 `suggest_title`의 사용자 주제 시작점이다.

`ChatHistoryPanel._ChatRow` (`iris/ui/monitor/chat_history_panel.py`)  
DB 제목을 다시 요약하지 않는다. 버튼은 24자, 툴팁과 편집칸은 저장값 전체다. 24자 절단은 표시만 자른다. 저장값이 이미 질문 토큰이면 툴팁도 질문이다.

`ChatSession.record` (`iris/runtime/chat_session.py`)  
메모리 `history`에 먼저 넣고 DB에 쓴다. DB 예외는 문자열로 돌려주고 메모리는 유지한다. 화면의 다음 턴과 목록 제목이 어긋날 수 있다. `drop_last_user`는 DB 예외를 삼킨다.

`MainWindow._record_history`  
`record` 뒤에 위키 히스토리를 남기고, user/assistant이면 목록을 다시 그린다. 제목을 따로 만들지 않는다. 목록이 질문처럼 보이는 것은 여기서 잘린 것이 아니라, 이미 그렇게 저장된 `title`이다.

### 4.2 채팅 저장·표시에서 손댈 자리

SQL `INSERT`/`UPDATE`는 바인딩이다. 제목 문자열이 쿼리에 붙지 않는다.

사이드바 제목은 `QPushButton.setText`와 `QLineEdit`이다. HTML로 해석하지 않는다.

채팅 본문은 `chat_renderer._markdown_body_to_html`이 markdown을 HTML로 만든 뒤 `_sanitize_chat_html`을 통과한다. 제거 대상은 `script`, `style`, `iframe` 세 태그뿐이다. 확장자는 `nl2br`, `fenced_code`, `tables`, `sane_lists`이고, raw HTML을 끄는 설정은 없다. Qt 리치 텍스트는 스크립트 실행이 좁지만, 남는 태그와 `img` 주소는 이 필터를 지나간다. `_style_img_tag`는 `img`를 다시 쓰되, 주소 스킴을 거절하지는 않는다.

대화 본문은 `ChatSession.history`로 다음 요청에 다시 들어간다. 채팅에 붙은 문장이 이후 턴의 지시가 된다. 제목 함수와는 별개이고, 도구 호출이 있는 턴에서 본문 지시가 동작으로 이어질 수 있다.

첨부 본문은 사용자 `content`에 한 덩어리로 저장된다. id 10·15의 첫 메시지에 파일 경로와 `[첨부 파일]`이 들어 있다. `first` 기준이면 그 토큰이 제목에 섞인다. 지금 설정은 `last`라 최근 5건의 저장 제목에는 경로가 없다. `suggest_title(first)`를 같은 메시지에 돌리면 `첨부 파일`, `자료 본문`이 제목 토큰으로 나온다.

`model_content`는 메시지 컬럼으로 분리되어 있다. 제목은 `content`만 본다. 화면에 보이는 문장과 모델에 넘긴 문장이 다르면 제목은 화면 쪽을 따른다.

## 5. 개선 자리

손댈 곳은 새 요약기가 아니라, 이미 갈라진 계약이다.

1. `suggest_title`이 비서 본문을 읽지 않는다. 설정 문구와 `summarize_reply`가 말하는 답변 요약은 이 자리가 비어 있다. 기준을 답변으로 둘 거면 여기서 읽고, 사용자 토큰으로 둘 거면 설정 문구를 그 기준으로 고친다.
2. `summarize_work_title`은 질문과 다른 문장을 만들지 못해도 사용자 단어를 반환한다. 질문의 조사만 뺀 문자열은 거절하고, 그때는 `새 채팅`으로 두거나 답변 경로로 넘긴다.
3. `_maybe_refresh_title`의 갱신 조건이 `suggest_title(last)`와 다르다. 기록 전에 비교하는 주제를, 함수가 고른 마지막 주제와 같게 둔다. id 10처럼 중간 문장이 고정되는 틈이 여기다.
4. `InterruptedTitleTests`와 `test_chat_conversations.py`가 서로 다른 제목을 단언한다. 계약을 하나로 정한 뒤 실패하는 쪽을 그 계약에 맞춘다.
