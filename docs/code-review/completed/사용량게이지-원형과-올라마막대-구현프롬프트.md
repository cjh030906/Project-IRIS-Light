Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- 증상 1: 선택 모델 옆 원형 표시가 사용한도처럼 거의 움직이지 않는다.
  구현은 iris/ui/widgets/context_ring.py ContextRingWidget.
  배치: iris/ui/chat/chat_panel.py 입력창 오른쪽, 모델명 왼쪽 18px.
  값: iris/ui/window/main_window.py _refresh_context_gauge.
  사용량은 글자 수//3, 한도는 Ollama /api/show 의 *.context_length.
  실패하면 128000을 _context_limit_cache 에 세션 동안 고정한다.
  갱신은 메시지 기록·응답 종료·대화 전환·모델 변경뿐이고, 스트리밍 중에는 멈춘다.
- 증상 2: 좌측 사이드바 SYSTEM METRICS 의 올라마 한도 막대(사용자가 말하는 우측 한도 바)가
  처음부터 숫자가 없거나 0으로 보인다.
  구현: iris/ui/monitor/system_metrics_panel.py 의 sess/week 행.
  수집: iris/infrastructure/ollama_usage.py fetch_ollama_quotas,
  iris/system/api_quota_worker.py, main_window._on_api_quotas / _maybe_refresh_ollama_quota.
  지금 출처는 ollama.com/settings HTML + OLLAMA_CLOUD_COOKIE 또는 ollama_cookie.txt.
  쿠키가 없고 /api/me 만 참이면 used=0,total=0 자리표시자를 그려 막대가 빈다.
  월간 필드는 없다. 라벨은 SESS, WEEK.
  자검 iris/ui/_check_ollama_quota_refresh.py 와 ollama_usage.py __main__ 이
  %LOCALAPPDATA%/iris-light/ollama_usage.json 실사용 파일을 테스트 숫자로 덮어쓴다.
- 이미 있는 로그인. 새로 만들지 말 것:
  - iris/system/ollama_server.py begin_ollama_cloud_login / open_ollama_app
  - iris/ui/workers/ollama_workers.py start_ollama_login_watch (데몬 /api/me 감시, UI 스레드 금지)
  - main_window._on_ollama_cloud_login_clicked / _apply_confirmed_ollama_login
    (확인 뒤 _maybe_refresh_ollama_quota(force=True) 가 이미 있다)

Goal:
1) 원형은 숫자를 숨기지 않고, 한도 조회 실패를 128000으로 고정하지 않으며, 응답이 쌓이는 동안 갱신된다.
   이름이 cloud 인 모델의 원형은 세션 사용 퍼센트다. 그 외 모델의 원형은 컨텍스트 비율이다.
2) 세션·주간 막대는 Iris를 처음 설치하고 처음 쓸 때부터, 사용자가 쿠키 파일을 만들거나
   DevTools를 열지 않아도 숫자와 함께 보인다.
3) 그 연결이 안 되어 있으면 Iris가 같은 실행에서 한 번 기존 로그인 절차로 붙이고,
   데몬 로그인이 확인되면 막대를 채운다. 비밀번호를 Iris가 입력하지 않는다.

Constraints:
- YAGNI: 아래 Interface 밖 금지. 막대를 오른쪽 창으로 옮기지 말 것. 월간 행을 만들지 말 것.
  새 설정 화면·새 마법사 스텝 금지.
- Surgical: 아래 파일과 그 테스트만. 무관 리팩터·테마 금지.
- 새 의존성 금지. unittest 또는 기존 모듈 self-check 만.
- UI 스레드에서 /api/show, /api/me, ollama.com HTTP, 로그인 대기를 하지 말 것.
- 쿠키·세션 원문을 로그·채팅·툴팁에 남기지 말 것.
- 콘솔 창 금지 (no-console-windows.mdc).
- 사용자에게 ollama_cookie.txt 를 만들라고 안내하는 툴팁을 남기지 말 것.
- 로그인 창은 프로세스당 자동 1회. 매 채팅·매 새로고침마다 띄우지 말 것.
- 자검·self-check 는 임시 디렉터리의 캐시만 쓴다. 실사용 ollama_usage.json 을 쓰지 말 것.

Interface (구현 계약):

1) 원형 게이지
   - set_context_usage 옆 경로를 추가하지 말고, 기존 set_usage(used, limit) 를 유지한다.
   - _context_limit_for:
     - /api/show 가 비거나 context_length 가 없으면 캐시에 넣지 않는다. 그 호출의 반환만 128000.
     - 다음 갱신에서 다시 조회한다. 성공한 값만 캐시한다.
     - API 런타임(parse_runtime_model_id 가 있는 모델)은 Ollama /api/show 를 호출하지 않는다.
       한도는 128000을 쓰되 캐시 키를 모델 id로 남긴다. 실패 캐시와 구분되게 성공으로 저장해도 된다.
     - 로컬·클라우드 Ollama 모델은 반환값을 min(context_length, 설정의 ollama_num_ctx) 로 한다.
       ollama_num_ctx 가 없거나 0이면 context_length 만.
   - 클라우드 판별은 기존 MainWindow._is_cloud_model.
     cloud 모델이고 세션 할당(total==100, 0<=used<=100)이 _quota_by_key["sess"] 에 있으면
     원형은 set_usage(round(used), 100) 이고 툴팁은 "세션 사용 n%".
     세션 값이 없으면 컨텍스트 비율로 폴백한다.
   - 컨텍스트 비율의 툴팁은 "컨텍스트 used / limit (n%)".
   - 생성 중(_busy)에는 1초 타이머로 _refresh_context_gauge 만 호출한다. 타이머가 /api/show 를
     매번 치지 않게, 한도는 캐시가 있을 때만 쓰고 없으면 직전 limit 를 유지한다.
     턴이 끝나면 타이머를 멈춘다.
   - 원형 클릭이 모델 목록을 여는 동작은 유지한다.
   - 호 색·18px 크기는 유지한다.

2) 막대 데이터 — 쿠키 파일 없이
   fetch_ollama_quotas 우선순위:
   a) 로컬 데몬 POST /api/me JSON.
      세션·주간 퍼센트가 들어 있는 키만 읽는다.
      없는 키를 0으로 만들지 말 것. 응답 원문을 로그에 남기지 말 것.
      키 후보는 구현 시 실제 필드명 한 세트를 함수 주석과 단위 테스트 픽스처에 고정한다.
      필드가 전혀 없으면 이 단계는 빈 결과이고 실패가 아니다.
   b) a가 비고 ollama_cloud_signed_in() 이 참이면, 그 데몬 세션으로 사용량을 한 번 더 읽는다.
      사용자가 쿠키 파일을 두지 않아도 되어야 한다.
      데몬이 사용량 필드를 주지 않으면 HTML 스크랩을 성공 조건으로 두지 말 것.
      이 단계가 불가면 이유 문자열만 반환하고 0% 캐시를 쓰지 않는다.
   c) 기존 resolve_ollama_cookie / settings HTML 은 폴백이다.
      HTML에 "Session usage" 또는 "Weekly usage" 가 없으면 캐시를 쓰지 않는다.
      파싱된 키만 캐시를 갱신한다. 없는 쪽을 0으로 덮어쓰지 말 것.
   d) 캐시는 7일 이내만 표시한다. 30일 stale 폴백은 삭제한다.
      캐시 시각은 막대 툴팁에만 적는다.
   - total<=0 인 ApiQuota 는 만들지 않는다. 로그인만 된 자리표시자(used=0,total=0) 를 삭제한다.
   - 사용 0% 는 유효하다. used=0,total=100 이면 행을 보여주고 막대는 0, 글자는 0% 이다.

3) 막대 표시
   - 라벨은 "SESS", "WEEK". 키는 sess, week 유지.
   - apply_quotas: total<=0 이거나 키가 없으면 그 행은 hide.
   - 두 값이 모두 total==100 이면 두 행을 show.
   - 클릭 새로고침(ollama_refresh_requested)은 유지한다.
   - 툴팁은 "한도 대비 사용 n% · 클릭하면 다시 읽기" 와 캐시 시각. 쿠키 경로 문구 삭제.
   - 색 분기 주석을 코드와 맞춘다. 40% 미만 연녹, 80% 미만 파랑, 그 이상 빨강.

4) 첫 설치·첫 실행부터 자동 연결
   테스트 모드(_test_mode)가 아닐 때, 메인 창이 뜬 뒤 워커에서만:
   - 데몬이 꺼져 있으면 기존 ensure_ollama_running. 기다림은 워커 안.
   - 로그인되어 있고 2)가 세션·주간 퍼센트를 주면 막대를 바로 채운다. 로그인 창을 열지 않는다.
   - 로그인이 거짓이면 이 프로세스에서 한 번만 begin_ollama_cloud_login + start_ollama_login_watch.
     성공 콜백은 _apply_confirmed_ollama_login. 채팅에 긴 안내를 추가하지 말고 활동 로그 한 줄만.
     앱이 없으면 기존처럼 브라우저 signin 폴백(begin_ollama_cloud_login 이 이미 한다).
   - 로그인은 참인데 2)가 퍼센트를 못 주면 막대를 그리지 않고, 워커에서 5초 간격으로 재조회 2회.
     그래도 없으면 로그인 창을 다시 열지 않는다. 활동 로그 한 줄:
     "올라마 사용량을 아직 읽지 못했습니다."
   - 사용자가 이번 실행에서 로그인을 끝내지 않으면 행은 숨긴다.
     다음 Iris 실행에서 위 순서를 다시 한 번 한다.
   - 설치 마법사에서 이미 /api/me 가 참이 된 뒤 메인 창이 열리면 로그인 창을 건너뛰고 조회만 한다.
   - 수동 클릭 새로고침은 자동 1회 제한과 별도이다. 다만 클릭이 로그인 창을 또 열지는 않는다. 조회만.

5) 자검이 실사용 캐시를 덮지 않음
   - write_usage_cache / read_usage_cache 가 경로 인자를 받거나, 테스트는 임시 디렉터리를
     LOCALAPPDATA 대신 쓰게 한다.
   - iris/ui/_check_ollama_quota_refresh.py 의 write_usage_cache(7.7, 11.1) 와
     ollama_usage.py __main__ 의 write_usage_cache(0.2, 4.1) 가
     사용자 프로필의 ollama_usage.json 을 만들지 않아야 한다.
   - 부분 파싱·0 미기록·total 0 숨김·클라우드 원형이 세션 %를 쓰는 경우를 같은 자검 또는 unittest에 넣는다.

Implementation order:
  Phase A: ollama_usage 조회 우선순위, total 0 제거, 캐시 부분 갱신, 자검 임시 경로
  Phase B: 막대 라벨·숨김·툴팁
  Phase C: 첫 실행 자동 로그인 1회 + 로그인 확인 뒤 막대 채움 + 재조회 2회
  Phase D: 원형 한도 캐시, cloud 세션 %, 생성 중 1초 갱신
  Phase E: 이 문서 상태 표를 완료로 고치고 한국어로 요약
