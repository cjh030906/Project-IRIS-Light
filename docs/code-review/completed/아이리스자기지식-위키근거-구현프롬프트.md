# Prompt: 아이리스 구조 질문은 소스 노트만 근거로

배경:

- `docs/code-review/completed/아이리스자기지식-위키근거-현황.md` (IRIS-REV-2026-1003-01)

위키 화면의 `obsidian-vault/코드`는 채팅 검색에 없다. 노트는 docstring 첫 줄만 담고, `ide_tiler` 노트는 아직 70:30이다. 구조 질문인데 0건이어도 그 사실이 프롬프트에 들어가지 않는다.

이 프롬프트는 그 세 자리만 메운다. 사용자 위키 색인과 테이블은 그대로 둔다.

---

```text
Context:
- 사용자 노트 검색은 wiki_note_index.wiki_prompt_for_query. 헤더는 「Iris Wiki 노트 (저장된 자료)」. 테이블은 wiki_notes.
- 볼트 코드 노트는 obsidian-vault/코드 와 obsidian-vault/Iris Light. list_notes 의 docs/ 경로로만 화면에 있다.
- generate_code_docs 는 docstring 첫 줄만 굽고, 런타임이 다시 부르지 않는다. ide_tiler.md 설명은 70:30, 소스 docstring 은 80:20 과 계약 문단이다.
- 근거 게이트는 answer_grounding.settle_grounded_answer. today|stored 이고 근거가 있을 때만 숫자·영문 대문자·따옴표를 자른다.
- 채팅은 PastChatsWorker(3초)와 시간 초과 시 키워드 경로가 wiki 블록을 _pending_wiki_notes 에 넣는다.

Goal:
1. 구조·커스텀 질문만 코드 노트를 찾는다. 「타일 비율이 어떻게 되지」「이 화면을 어떻게 고치지」「아이리스는 어떻게 짜여 있어」는 참. 「함수 짜줘」「위키에 저장해줘」「오늘 날씨」는 거짓.
2. 검색 대상은 볼트 코드/ 와 Iris Light/ 뿐이다. wiki_notes 에 넣지 않는다. 블록 제목은 「아이리스 소스 노트」. 「저장된 자료」와 한 문자열로 섞지 않는다. 최대 3건, 노트당 800자, 합 2400자.
3. 노트가 `iris/...py` 를 가리키고, 소스가 노트보다 새거나 노트 본문에 모듈 docstring 전체가 없으면, 발췌는 그 docstring 전체다. 노트 첫 줄(70:30)은 넣지 않는다. .cursor/rules 전문은 넣지 않는다.
4. 구조 질문인데 0건이면 「0건」과 「없다고만」이 있는 블록을 넣는다. 발췌가 있으면 settle 의 kind 를 iris 로 두고, 근거에 없는 숫자·영문 대문자·따옴표 문장만 빼고 「노트에 없다.」를 남긴다.
5. wiki.search 는 사용자 히트와 코드 히트를 다른 목록으로 돌려준다. 코드 경로에 user/ 를 붙이지 않는다.

Constraints:
- 매 턴 볼트 전문을 넣지 말 것. 시스템 문구에 타일·구조 설명을 추가하지 말 것.
- 70:30 이 남은 노트 문장을 근거로 올리지 말 것.
- 새 MainWindow 속성은 __init__ 에서 만든다. 검색은 UI 스레드에서 하지 말 것.
- 사용자 위키 0건 블록과 format_note_prompt([]) == "" 는 유지한다.

Interface:

1) 구조 질문 (iris/knowledge/answer_grounding.py)
   wants_iris_structure(text) -> bool
   settle_grounded_answer: kind 가 iris 이고 evidence 가 있으면 missing 은 「노트에 없다.」
   evidence_corpus(..., code="") — 이전 대화 텍스트는 넣지 않는다.

2) 코드 노트 (iris/knowledge/code_note_prompt.py)
   search_code_notes(vault, query, *, project, limit=3) -> list
   code_prompt_for_query(vault, query, *, on_empty=False, project=None) -> str
   - on_empty 가 거짓이고 0건이면 "".
   - 헤더에 「아이리스 소스 노트」. 「저장된 자료」는 없다.
   - 경로 표기는 docs/코드/... 또는 docs/Iris Light/...

3) 워커·채팅
   PastChatsWorker(..., code_on_empty=False). ready payload 에 code.
   MainWindow.__init__: _pending_code_notes, _turn_iris_lookup.
   구조 질문이면 4자 미만이 아니어도 워커를 돌린다. today 이면 code 는 빈다.
   코드 블록은 위키 블록과 다른 system 메시지다.
   _ground_shown: 구조 질문이고 kind 가 other 이면 kind=iris, evidence 에 코드 블록을 넣는다.

4) wiki.search (iris/ui/control_actions/wiki.py)
   기존 hits 는 그대로. code_hits 를 따로. source 는 code-note. rel_path 는 docs/ 로 시작한다.

5) 확인
   python -m iris.knowledge.code_note_prompt
   python -m iris.knowledge.answer_grounding
   python -m iris.knowledge.wiki_note_index
   가짜 노트 70:30 + 소스 docstring 80:20 이면 발췌에 80:20 만 있고 70:30 은 없다.
   실제 obsidian-vault/코드/system/ide_tiler.md 가 있으면 「타일 비율」검색도 같다.
   0건 블록에 0건·없다고만. 구조 질문이 아닌 빈 결과는 "".
   wants_iris_structure 가 위 세 질문에서 참, 짜줘·저장해줘·날씨에서 거짓.
   evidence 가 80:20 일 때 답의 70:30 문장은 빠지고 「노트에 없다.」가 남는다.
```
