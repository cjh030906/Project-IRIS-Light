# Prompt: 오늘 사실·저장 자료·실행 보고만 근거에 묶는다

배경:

- `docs/code-review/completed/답변근거강제-환각감소-현황과-개선안.md` (IRIS-REV-2026-1002-01)

프롬프트에 “지어내지 마라”만 있는 일반 채팅은 모델이 도구를 안 불러도 답이 나간다. 위키 검색이 0건이면 그 문장 자체가 빠지고, 인용 칩은 모델이 쓴 주소를 그대로 그린다. 파일 쓰기만 도구 ok와 디스크로 완료 문장을 지운다.

이 프롬프트는 그 빈 자리를 채팅에 넓힌다. 환각을 0으로 만들지 않는다. 오늘 사실, 저장·첨부, 실행 보고, 이번 턴에 없는 인용 주소만 근거 밖으로 나가지 않게 한다.

---

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- 오늘 사실의 검색은 이미 있다. iris/runtime/routine_search.py 의 run_search, format_evidence.
- 위키 발췌는 wiki_prompt_for_query → format_note_prompt. 0건이면 빈 문자열이라 “없으면 없다고 해라”가 전달되지 않는다.
- 첨부·경로·URL 발췌는 material_excerpt 와 첨부 model_content. 발췌 밖 문장은 지우지 않는다.
- 파일 쓰기 게이트는 “처리 완료|생성하겠습니다|작성했습니다|파일을 열었습니다|저장했습니다”만 본다.
- 인용은 iris/core/chat_citations.py 가 본문 URL을 칩으로 그린다. 이번 턴 결과와 대조하지 않는다.
- 이전 대화 헤더는 past_chats._HEADER. “참고용”이고 “이전 대화에서”라고 밝히라고 한다.
- 도구 성공 진행 줄은 “<name> ok”. counts_as_tool_ok 가 센다. completed / running 은 성공이 아니다.

Goal:
1. 질문 종류는 앱이 가른다. today(뉴스·날씨·시세·경기 결과) / stored(위키·노트·첨부) / action(저장·전송·실행 요청) / other(글·계산·코드·의견). 모델에게 검색 여부를 맡기지 않는다.
2. today 는 채팅도 run_search → format_evidence. 키가 없거나 결과가 없거나 시간 초과면 그 실패 문장만 답하고 모델 호출을 하지 않는다. 검색이 되면 근거 블록을 사용자 메시지 바로 앞에 넣는다.
3. 저장 자료를 묻는 질문에서 위키 0건이면 빈 문자열 대신 “0건, 없다고만 해라” 블록을 넣는다. 발췌 또는 검색 결과가 있으면, 답의 문장 중 근거에 없는 숫자·영문 대문자 이름·따옴표 고유명만 빼고 “발췌에 없다” 또는 “검색 결과에 없다”를 남긴다. 문장 전체를 대조하지 않는다.
4. 이번 턴 tool_ok 가 0이면 “저장/검색/전송/실행/처리/완료” 류 문장만 “이번 턴 도구 결과: <이름> · ok 없음” 한 줄로 바꾼다. today 이고 검색 근거 블록이 있으면 “검색했”만 남긴다. 앱이 이미 검색했다. 파일 쓰기 게이트의 표현 목록은 늘리지 않는다.
5. today·stored 근거가 있는 답에서, 그 근거 텍스트에 없는 http 주소는 본문에서 뺀다. 뺀 횟수를 센다.
6. 이전 대화 헤더 문구는 유지한다. 사실 근거 문자열에 넣지 않는다.
7. 볼 숫자는 세 개뿐이다. search_fail_long, claim_without_ok, unknown_url.

Constraints:
- 모든 턴에 웹 검색하지 말 것. 위키 전문을 넣지 말 것. 시스템 프롬프트에 금지 문장만 추가하는 것으로 끝내지 말 것.
- 이전 대화 답을 검증된 사실로 쓰지 말 것. Instructor·별도 검증 모델을 넣지 말 것.
- 새 MainWindow 속성은 __init__ 에서 만든다. 슬롯 밖으로 예외를 보내지 말 것.
- 검색은 UI 스레드에서 하지 말 것. today 는 PastChatsWorker 안에서 run_search.
- 한글 고유명 전체(조사 포함)는 대조하지 않는다. 숫자, 영문 대문자 토큰, 따옴표 안만.

Interface:

1) 분류·게이트 (iris/knowledge/answer_grounding.py)
   classify_turn(text) -> "today" | "stored" | "action" | "other"
   turn_has_grounding_material(text, history, attachments) -> bool
   - other 이고 첨부가 있으며 코드·작성 요청이 아니면 stored 로 올린다.
   wants_wiki_lookup(text) -> bool
   - 위키·노트·저장해 둔 자료를 묻는 말. “저장해/넣어 줘/보내/실행해”면 거짓.
   today_search(query) -> TodaySearch
   - run_search. 뉴스·속보면 google_news, 그 외 google. 질의는 사용자 문장 앞 180자.
   - ok 가 아니면 reply 만. evidence 는 format_evidence.
   search_timeout_reply(query) -> str
   settle_grounded_answer(text, *, kind, evidence, web_failed, failure_reply, tool_ok, tool_lines) -> str
   - web_failed 이고 실패 문장 밖에 80자 초과면 실패 문장으로 바꾸고 search_fail_long.
   - kind 가 today|stored 이고 evidence 가 있으면 근거 밖 숫자·영문 이름·따옴표만 문장 단위로 제거.
   - tool_ok==0 이면 실행 보고 문장만 도구 한 줄로 바꾸고 claim_without_ok.
   - evidence 가 있으면 그 안의 URL만 남기고, 뺀 개수만큼 unknown_url.
   counts() -> dict
   evidence_corpus(web, wiki, material) -> str
   - 이전 대화 텍스트는 인자로 받지 않는다.
   material_from_history(history) -> str
   - 마지막 사용자 메시지의 [자료 본문] 또는 BEGIN ATTACHMENT TEXT 뒤.

2) 위키 0건 (iris/knowledge/wiki_note_index.py)
   format_note_prompt([]) 는 계속 "".
   wiki_prompt_for_query(..., on_empty: bool = False)
   - 발췌가 있고 on_empty 이면 empty_stored_block(query). “0건”과 “없다고만”이 들어간다.

3) 워커 (iris/ui/workers/past_chats_worker.py)
   search_today, wiki_on_empty.
   - today 검색이 실패하면 past·wiki 없이 web_error 로 ready.
   - 검색이 된 뒤 past 조회가 실패해도 검색 블록은 ready 로 보낸다.

4) 채팅 (iris/ui/window/main_window.py)
   __init__: _turn_ask_kind, _turn_wiki_lookup, _turn_web_error, _turn_search_failure_reply, _pending_web_evidence, _turn_tool_lines.
   - 턴 시작에 도구 줄·종류를 비운다. 턴 종료에 근거 블록을 비운다.
   - today 는 모델 전에 워커 검색. 실패·시간 초과(8초)면 실패 문장만 남기고 _launch_chat_turn 을 호출하지 않는다.
   - 성공한 웹 근거는 시스템 메시지 중 사용자 말 바로 앞에 넣는다. today 에는 위키 발췌를 얹지 않는다.
   - 이전 대화는 기존 _apply_past_chats 그대로.
   - _on_hermes_tool_progress 는 진행 줄을 _turn_tool_lines 에 남긴다.
   - _gate_chat_completion: 위키 게이트가 문장을 바꿨으면 그 결과에 settle. 파일 게이트가 문장을 바꿨으면 그 결과만 반환(표현 목록은 그대로). 둘 다 아니면 settle.
   - 세 숫자가 늘면 활동 로그에 한 줄.

5) 확인
   python -m iris.knowledge.answer_grounding
   python -m iris.knowledge.wiki_note_index
   python -m iris.runtime.routine_search
   python -m iris.knowledge.wiki_claim
   python -m iris.ui._check_file_write_claim
   오늘 날씨 / 위키에 있어 / 저장해줘 / 함수 짜줘 가 각각 today, stored, action, other.
   검색 실패 답변 자리에 실패 문장 밖 긴 본문이 있으면 search_fail_long 이 늘고 실패 문장만 남는다.
   tool_ok 0 인 “실행했습니다” 는 도구 한 줄로 바뀌고, “처리 완료” 파일 게이트 정규식은 그대로다.
```
