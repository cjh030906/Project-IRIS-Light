# Prompt: 채팅이 모델을 건너뛰는 6종 → 에이전트 도구

아래 블록을 구현 계약으로 따른다.

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- _execute_user_turn 이 Hermes 전에 정규식으로 끊는 여섯 가지:
  IDE 켜기/끄기, 홈·메일·캘린더·위키·마이크, 위키 저장, PDF 저장,
  GitHub MCP·스킬 설치, 사진에서 코드 쓰기 + 문장 키워드로 project.run.
- IDE·화면·마이크·위키 가져오기·project.run·project.write_file 도구는 이미 있다.
- PDF는 프로세스 안에서 PyMuPDF를 돌리면 IRIS가 죽는다. 자식 프로세스 save_pdf 만 허용.
- GitHub 설치의 다음 턴(비밀 키·디렉터리)은 모델에 비밀을 보내지 않는다.
- 파일 쓰기 완료 문장 게이트(settle_completion_claim)는 유지한다.
- 액션 카탈로그 iris/ui/control_actions/action_catalog.json 은 register() 와 같아야 한다.

Goal:
1) Hermes가 켜져 있으면 위 여섯 의도는 모델을 건너뛰지 않는다. 모델이 iris_invoke 로 처리한다.
2) Hermes가 꺼져 있으면 기존 로컬 핸들러를 그대로 쓴다.
3) 비밀·디렉터리 대기(_pending_ext)는 Hermes 여부와 상관없이 로컬에서 이어 간다. 새 GitHub URL은 Hermes가 켜져 있으면 모델로 보낸다.
4) 없는 도구 세 개를 추가한다.
   - note.export_pdf
   - extension.install_github
   - project.write_image_code
5) Hermes가 켜져 있으면 응답 뒤 is_run_request 로 project.run 하지 않는다. 실행은 모델의 project.run 만.
6) 시스템 문장과 Hermes MEMORY nudge 가 "Iris가 로컬에서 PDF·위키를 처리한다"고 말하지 않고, 위 도구를 부르게 한다.

Constraints:
- 정규식 파서(is_wiki_save_intent, is_pdf_save_intent, parse_extension_request, image_write_request, is_run_request)는 삭제하지 않는다. Hermes가 꺼진 경로와 대기 대화가 쓴다.
- 메일·캘린더 패널의 워크스페이스 정규식도 같은 게이트를 탄다.
- Companion 80:20, IDE new-window, project.write_file 계약 유지.
- control_actions 모듈은 MainWindow 를 import 하지 않는다.
- note.export_pdf, extension.install_github, project.write_image_code 는 UI 스레드 밖에서 시작한다. 위젯 접근은 기존 _call_on_ui.

Interface:
1) iris/runtime/agent_local_gate.py
   - hermes_owns_local_intents(hermes_enabled: bool) -> bool
   - True 이면 여섯 의도의 신규 가로채기를 하지 않는다.

2) main_window
   - _execute_user_turn: owns 이면 IDE·위키·PDF·워크스페이스·사진 파이프를 호출하지 않는다.
     owns 이면 extension 은 allow_new=False. owns 가 아니면 기존 순서(IDE → 위키 → PDF → extension → 워크스페이스).
   - _try_local_extension_install(turn, allow_new=True). allow_new 가 False 이고 새 URL이면 pending 을 지우고 False.
   - 메일·캘린더 전송: owns 이면 _try_local_workspace_control 을 건너뛴다.
   - _try_reveal_local_vibe_code: run_locally 는 owns 가 아니고 is_run_request 일 때만.
   - _chat_messages_with_project_context: 위키·PDF·GitHub·사진 코드·실행·화면 전환을 도구 이름으로 안내.
     "Iris가 직접 처리한다" 문장 제거.

3) iris/ui/control_actions/agent_turn.py — register_agent_turn_actions
   - note.export_pdf: content 필수. path 없으면 ~/Documents/IRIS/iris-note.pdf. save_pdf 만 사용.
     content 가 비면 자식 프로세스를 띄우지 않고 content required.
   - extension.install_github: url 필수. kind 는 auto|mcp|skill, 그 외는 auto.
     install_from_request. status 가 failed|refused 이면 실패.
     needs_input 이면 ok 와 함께 _pending_ext 를 UI 스레드에서 채운다 (url, kind, missing, need_dir, secrets, directory).
     mcp_added 이면 restart_hermes_gateway. installed|already 이면 위키 카탈로그 동기화.
   - project.write_image_code: image 파일과 rel_path 필수. 비전 추출은 워커에서, 쓰기는 project_write_file(open=true) 을 UI 스레드에서.
     등록은 _first_class_ide_trigger 로 감싼다. 모델이 없으면 model required.
   - 요약 문장에 인자 이름과 "ok 없이 성공이라고 말하지 말 것"을 넣는다.

4) control_bindings._register_actions 에서 register_agent_turn_actions 호출.
   runs_off_ui_thread 에 세 액션을 넣는다.
   action_catalog.json 을 register() 결과로 맞추고 건수를 115로 한다.

5) hermes_memory_nudge 를 v17 로 올린다.
   위키는 keyword shortcut 없이 wiki.import_content / wiki.write_user_note.
   PDF는 note.export_pdf. GitHub는 extension.install_github. 사진은 project.write_image_code.
   "handle locally" 문구는 넣지 않는다.

6) 자검 iris/ui/_check_agent_turn_tools.py
   - hermes_owns_local_intents True/False.
   - 세 액션이 카탈로그에 있다.
   - content 없음, url 없음, image 없음, 없는 이미지 경로는 ok False. 네트워크·PDF 자식 프로세스를 띄우지 않는다.

검증:
.venv\Scripts\python.exe -m iris.ui._check_agent_turn_tools
.venv\Scripts\python.exe -m iris.ui._check_control_action_split
.venv\Scripts\python.exe -m iris.ui._check_wiki_save_intent
.venv\Scripts\python.exe -m iris.ui._check_pdf_export
.venv\Scripts\python.exe -m iris.system._check_github_extension_install
.venv\Scripts\python.exe -m iris.ui._check_file_write_claim
```
