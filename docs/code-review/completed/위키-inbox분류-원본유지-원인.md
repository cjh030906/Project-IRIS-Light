# 위키 inbox 분류 — 옮겼다고 말하고 원본은 inbox에 남는 문제

| 항목 | 내용 |
|---|---|
| 문서 번호 | IRIS-REV-2026-1002-01 |
| 작성일 | 2026-10-02 |
| 대상 | 채팅 13번, 「내용들 학습 자료 강화학습 영어로 저장」 |
| 목적 | 분류·이동을 완료했다고 한 답이 위키 화면의 inbox와 다른 이유 |
| 조사 범위 | 채팅 DB, `~/.iris-light/iris-wiki` 파일, 위키 컨트롤, 분류·저장, 턴 감독, 완료 게이트, 트리 UI |
| 하지 않은 일 | 코드 수정, inbox 정리, 스텁 노트 삭제 |

관련 이전 기록: `docs/code-review/위키재가공-말만하고안씀-원인과-개선안.md` (2026-09-30). 그때는 저장 후 수정이 파일에 안 닿았다. 이번은 쓰기는 됐지만, 요청한 이동·폴더 이름·본문과 결과가 다르다.

---

## 1. 결론

Iris는 inbox 문서를 `학습자료/강화학습`과 영어 이름 `fine-tuning` 폴더로 나눠 옮기지 않았다. 18분 동안 `wiki.write_user_note`로 **새 파일 21개**를 `학습자료/reinforcement-learning/` 아래에 만들었고, inbox 원본 120개는 그대로 두었다. 새 파일은 원문 복사가 아니다. 검색으로 볼 수 있는 짧은 발췌를 바탕으로 한 요약본이다.

위키 화면의 inbox가 분류되지 않은 채로 보이는 것이 맞다. 옮기는 도구가 없고, 완료 문장을 디스크와 대조하는 문도 이 요청을 통과시킨다.

---

## 2. 구조

요청이 파일과 화면까지 가는 경로다.

```
사용자 문장
  「학습 자료에서 강화학습, 영어로 파인튜닝 폴더를 만들고 분류해서 저장」
        │
        ▼
로컬 위키 저장 분기 (_try_local_wiki_save)
  조건: 「위키」+「저장」+ 주소/첨부/파일
  이번 문장에는 「위키」와 주소가 없음 → 타지 않음
        │
        ▼
Hermes 도구 루프 (모델이 도구를 고름)
  wiki.list_notes     경로·제목·폴더만. 본문 없음
  wiki.search         발췌 최대 800자
  wiki.open_note      화면만 연다. 본문을 모델에 돌려주지 않음
  wiki.write_user_note  제목+본문으로 새 md를 씀. 원본 삭제 없음
  (move / delete / read_note 는 카탈로그에 없음)
        │
        ▼
file_user_note
  rel_path 가 inbox 가 아니면 그 경로 그대로 생성
  분류기(classify_note)는 이번 턴에서 폴더 이름을 정하지 않음
        │
        ├─ 디스크: 학습자료/reinforcement-learning/**  (신규, 짧은 본문)
        └─ 디스크: inbox/**  (기존 120개, 변경 없음)
        │
        ▼
트리 UI (ObsidianDetailPanel.reload)
  user_root 의 md 를 전부 폴더로 그림
  inbox 와 학습자료 가 나란히 보임. inbox 가 비워지지 않음
        │
        ▼
완료 문장
  턴 감독·완료 게이트가 「이동 완료」를 파일 대조 없이 통과
  직후 대화 전환 → 「대화 전환으로 응답을 중단했습니다.」
```

저장 단위는 노트 하나다. 「폴더를 만들고 기존 노트를 그 안으로 옮긴다」는 동작은 이 경로에 없다.

## 3. 확인한 사실

대화는 `chat_conversations.id = 13`. 사용자 요청 `2026-10-02T18:58:17`, 완료처럼 보이는 답 `19:16:14` (2160자), 중단 문구 `19:16:15`.

새 파일 21개의 기록 시각은 `19:00:48`–`19:15:50`이다. 도구 쓰기는 실제로 돌았다. 그 다음 문장이 이동 완료를 말했다.

| 사용자가 요청한 것 | 디스크 |
|---|---|
| `학습자료/강화학습` | 없음 |
| 영어 이름 파인튜닝 폴더 (`fine-tuning` 또는 `파인튜닝`) | 없음 |
| inbox 문서를 그 안으로 분류·이동 | inbox 120개 유지 |
| 단계·카테고리별 원문 | `학습자료/reinforcement-learning/` 21개. 본문은 짧은 요약 |

`학습자료` 아래 실제 자식은 `reinforcement-learning`, `개발용어`, `딥러닝`뿐이다. 뒤의 둘은 이날 다른 채팅에서 만든 노트다.

크기 대조 (같은 주제, inbox 원본은 남아 있음):

| 주제 | inbox 원본 | 새로 쓴 파일 |
|---|---:|---:|
| 11.1 DeZero | `inbox/111-dezero-기초-….md` 14,812바이트 | `…/11.1-dezero-basics.md` 836바이트, 13줄 |
| 11.3 신경망 | `inbox/113-신경망-….md` 16,705바이트 | `…/11.3-neural-networks.md` 907바이트 |
| Anthropic 에이전트 | `inbox/building-effective-ai-agents-anthropic.md` 20,483바이트 | `…/agents-workflows/….md` 2,322바이트 |

색인 `wiki_notes`도 같다. inbox 120행, `reinforcement-learning` 21행. 새 행의 본문 길이는 261–1,269자다.

답변 표는 inbox를 14개로 적었다. 디스크 inbox는 120개이고, 강화학습 계열만 해도 같은 글의 시각 접미사 복제가 여러 개다. 1강·7강·13.1·13.4처럼 그 14개 표에 없던 파일도 새로 썼다. 그 원본은 inbox에 따로 있다. 표에 없는 글을 지어 낸 것이 아니라, 목록이 inbox 전체가 아니었다.

첫 질문(「inbox 안에 저장된 내용은」)의 14개 표도 같은 한계다. 전체 목록이 채팅에 나온 적이 없다.

## 4. 코드 리뷰

### 4.1 쓰기는 복사본이고, 이동이 아니다

`iris/ui/control_actions/wiki.py`의 `wiki_write`는 `file_user_note`만 호출한다. 성공 결과에는 `rel_path`, `place`, `ask_folder`가 있고, 지운 원본 경로는 없다.

`iris/knowledge/wiki_filing.py` `_explicit_rel`: 분류 중일 때 `inbox/`로 시작하는 경로만 버리고 다시 정한다. `학습자료/reinforcement-learning/...`처럼 inbox가 아닌 경로는 그대로 쓴다. 그래서 영어 슬러그 폴더가 생겼다. 분류기 `classify_note`는 이 경로를 고르지 않았다.

`iris/knowledge/iris_wiki.py` `write_user_note`는 부모 폴더를 만들고 파일을 덮어쓴다. 다른 경로의 파일을 지우지 않는다.

카탈로그(`action_catalog.json`)의 위키 액션은 list, open, reload, search, write, import_content, import_pages다. rename, move, delete가 없다. 모델이 「inbox에서 이동 완료」라고 말할 수 있는 도구 결과가 없다.

### 4.2 본문을 읽는 도구가 없다

`wiki_list`는 `rel_path`, `title`, `folder`, `source`만 돌려준다.

`wiki_search`는 `wiki_note_index._EXCERPT = 800`으로 자른 `excerpt`만 돌려준다.

`wiki_open`은 위키 화면을 열고 `{"rel_path": rel}`만 돌려준다. `IrisWiki.read_note`는 이 액션에 연결되어 있지 않다.

14KB 원문을 새 경로에 그대로 두려면 모델이 본문 전체를 `content`로 넣어야 한다. 도구가 본문을 주지 않으니, 쓴 파일은 발췌 수준의 요약이 된다. DeZero 원본 14,812바이트가 836바이트·13줄이 된 것이 그 결과다.

`write_inbox_note`는 제목, `source:` 줄, 본문, `updated` 줄을 붙여 저장한다. 짧은 `content`도 노트로 보이고, 도구는 ok를 돌려준다.

### 4.3 요청한 폴더 이름을 만드는 경로가 이번 턴에 쓰이지 않았다

`wiki_places.clean_field_name`은 분야 이름을 한 단계 슬러그로만 받는다. 슬래시를 허용하지 않아 `학습자료/강화학습/chapter-11` 같은 트리는 분류기 출력으로 나오지 않는다. 한글 `강화학습`은 `slugify_note_name`이 유지할 수 있다. 이번 파일은 그 함수를 거치지 않고, 모델이 넣은 `reinforcement-learning` 경로로 만들어졌다.

사용자가 말한 두 이름(강화학습, 영어 파인튜닝)을 경로로 강제하는 검사도 없다. `ask_folder: false`는 「분류기가 애매해서 inbox에 남겼다」가 아니라는 뜻이지, 「요청한 폴더로 옮겼다」는 뜻이 아니다. 명시 경로로 쓰면 `file_user_note`가 `ask_folder`를 항상 false로 둔다.

### 4.4 완료 문장을 막지 않는다

`iris/runtime/turn_followthrough.py`

- `_wiki_save_goal`은 목표에 「위키」(또는 wiki, 가져오)와 「저장」(또는 가져오)이 같이 있어야 한다.
- 이번 목표에는 「학습 자료」와 「저장」만 있고 「위키」가 없다. 감독 조건 밖이다.
- 설령 조건에 들어와도, 재시도는 `tool_ok_count == 0`일 때만이다. 이번엔 write가 ok였다. 스텁 21개도 성공으로 끝나고, 「inbox는 비었는가」「본문 크기가 원본과 같은가」는 보지 않는다.
- `_DONE`은 「저장했」 계열이다. 「이동 완료」「분류했습니다」만 있으면 여기에도 안 걸린다.

`MainWindow._gate_chat_completion`은 `file_write_claim.settle_completion_claim`만 호출한다. 그 정규식은 「처리 완료」「작성했습니다」「파일을 열었습니다」와 코드 펜스다. 위키 트리 문장(「분류해 저장했습니다」「inbox에서 이동 완료」)은 통과한다.

### 4.5 화면은 디스크를 그대로 보여 준다

`ObsidianDetailPanel.reload`는 `list_notes()` 전체를 폴더 트리로 만들고 `expandAll`한다. 새 폴더를 숨기지 않는다. inbox가 분류 안 된 것처럼 보이는 이유는 UI 필터가 아니라, inbox 파일이 삭제되지 않았기 때문이다. 120개와 시각 접미사 복제가 트리를 채운다.

`wiki_write`는 저장 후 그 노트를 연다. 마지막에 열린 쪽은 스텁일 수 있다. 사용자가 inbox 폴더를 누르면 원본이 그대로 있다.

### 4.6 대화 전환은 이미 말한 완료를 지우지 않는다

`conversations.INTERRUPTED_NOTE`는 `19:16:15`에 별도 비서 행으로 남았다. 완료 행(`19:16:14`)은 유지된다. 전환은 진행 중 도구를 끊을 수 있지만, 그 전에 쓴 21개 파일은 롤백되지 않고, 이미 저장된 「이동 완료」 문장도 바뀌지 않는다.

## 5. 원인

한 줄로 말하면, **분류 이동은 도구에 없고, 모델은 짧은 쓰기를 이동으로 말했다.**

1. 이 문장은 로컬 저장 분기에 들어가지 않는다. 주소도 없고 「위키」도 없다.
2. 모델은 본문을 받지 못한 채 `wiki.write_user_note`에 요약과 스스로 정한 경로를 넣었다.
3. 그 호출은 성공이다. inbox는 대상이 아니다.
4. 감독과 게이트는 그 성공과 「저장했습니다」를 완료로 둔다.
5. 사용자는 위키에서 inbox를 연다. 원본이 있으므로 분류가 안 된 것이 맞다.

9월 30일 재가공 건과 같은 지점은 「ok 없이 했다고 말한다」가 아니라, **ok가 있어도 그 ok가 요청(이동, 원문, 지정한 폴더 이름)을 증명하지 않는다**는 점이다.

## 6. 개선 범위

이번 문서에서는 고치지 않았다. 손을 댄다면 아래 순서가 맞다.

1. **이동은 앱 절차로 둔다.** 대상은 이미 있는 `rel_path`다. 읽기(`read_note`) → 요청한 폴더 이름으로 같은 바이트 쓰기 → 원본 삭제 → 트리 갱신. 모델이 본문을 다시 쓰지 않게 한다. 폴더 이름이 문장에 있으면(`강화학습`, `fine-tuning`) 그 문자열을 경로에 쓴다.
2. **완료 문장은 디스크와 맞춘다.** 「옮겼다」「분류했다」「inbox에서 이동」인데 원본이 아직 inbox에 있거나, 새 파일 크기가 원본보다 크게 작으면 그 문장을 보여 주지 않는다. 「새 요약 파일을 만들었고 inbox 원본은 그대로다」만 남긴다.
3. **감독 조건에 이 문장 형태를 넣는다.** 「학습자료」+「폴더」+「분류/저장」도 위키 정리로 본다. write ok 횟수만으로 멈추지 않고, inbox에서 빠졌는지 본다.
4. **목록 도구가 잘리면 개수를 같이 돌려준다.** `wiki.list_notes`가 120개인데 답이 14개로 시작하면, 그 14개만 정리해도 완료가 아니다.

스킬 문장을 더 넣는 것은 하지 않는다. 쓰기 도구가 ok를 주는 한, 금지 문장과 별개로 파일이 생긴다.
