# Prompt: 위키 재가공 — 말 대신 파일 절차

배경: `docs/code-review/위키재가공-말만하고안씀-원인과-개선안.md` (IRIS-REV-2026-0930-03).
첫 저장은 `import_to_wiki`라 빠르고 파일과 답이 같다. 「원문은 남기고 위에 정리, 문단마다 한국어」와 「정리된 노트를 열어」는 주소도 「위키」도 없어 그 분기를 빠져 Gemma가 정리했다고만 말한다. 노트는 그대로다.

이 프롬프트는 그 보고서의 3번 원인, 4번 같은 계통, 5번 개선안을 구현 계약으로 고정한다. 휴리스틱으로 raw/summarize 모드를 고르지 않는다. 사용자 문장은 닫힌 명령이고, 각 명령은 노트를 읽고 쓰는 함수다.

---

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- 빠른 저장: 주소·파일·첨부와 저장 요청은 모델을 부르지 않고 wiki.import_content raw 와 같다.
- 실패: 직전 노트 경로를 세션이 기억하지 않는다. 요약 모드는 본문을 요약으로 교체하고 24,000자에서 자른다. 문단 번역 함수가 없다.
  모델은 노트 본문을 못 읽고, wiki.write_user_note 한 번에 2만 자를 못 싣는다.
  완료 게이트는 IDE 코드 문구만 본다. 턴 감독은 목표에 「위키」+「저장」이 있을 때만 거짓 완료를 의심한다.
  Hermes 진행 로그는 status 가 tool 보다 먼저라 running/completed 만 남고, 성공 카운트는 " ok" 만 센다.
- 원문 품질: URL 본문은 표준 라이브러리 HTML 파서라 메뉴·Skip to main content 가 본문에 남는다.
- 이미 있는 것. 동작을 빼지 말 것:
  - import_to_wiki / wiki.import_content mode=raw
  - wiki.import_pages, file_write_claim 의 코드 펜스 게이트
  - summarize_for_wiki, chat_once (OllamaClient.chat_once_with_images)

Goal:
사용자 요청을 WikiCommand 로 읽고, Iris 가 아래 동작을 파일에 수행한다.
저장, 요약(원문 유지가 기본), 정리(위에 요약·아래 원문·문단 한국어), 열기, 삭제, 생성, 변경(제목·본문), 목록.
모델은 요약 한 번과 문단 번역에만 쓴다. 계획 턴을 열지 않고, 채팅에는 반환된 경로와 결과만 보인다.
「정리」가 있다는 이유만으로 본문을 요약으로 바꾸지 않는다.

Constraints:
- 새 에이전트 런타임, LangGraph, Instructor, tool_choice, 스킬 문장 추가 금지.
- Argos/LibreTranslate 금지. 문단 번역은 기존 chat_once.
- Firecrawl 은 지금처럼 본문이 비었고 키가 있을 때만.
- 첫 raw 저장은 모델 호출 없이 유지.
- Hermes 가 켜져 있어도 이 명령은 모델 루프보다 먼저 실행한다. IDE·화면·PDF 가로채기는 그대로 둔다.
- 「위키 화면 열어」처럼 화면만 여는 짧은 문장은 명령으로 잡지 않는다.
- 직전 노트가 있어도 「코드/함수/버그/파일」 정리는 위키 재가공이 아니다.
- Qt 슬롯 밖으로 예외를 보내지 않는다. 새 창 속성은 MainWindow.__init__ 에 만든다.
- 콘솔 창 금지. 노트 원문 전체를 진행 로그에 남기지 않는다.

Interface:

1) 본문 추출 (iris/knowledge/content_extract.py)
   html_to_article(html, *, url="") -> (title, body)
   - trafilatura 가 본문을 돌려주면 그 글을 쓴다. 메뉴 문구가 줄어들어야 한다.
   - 비었거나 실패하면 표준 파서로 돌아가되 script/style/nav/header/footer/aside 는 건너뛴다.
   - fetch_url_text 의 표준 경로는 이 함수를 쓴다. Firecrawl 순서는 유지.
   - 의존성: requirements.txt 에 trafilatura.

2) 명령 (iris/knowledge/wiki_command.py)
   WikiCommand: op, source, rel_path, title, body, content,
   keep_original, summarize, translate.
   op 는 save | reprocess | open | delete | create | update | list 만.
   parse_wiki_command(text, attachments=(), history=(), target="") -> WikiCommand | None
   - 주소·경로·첨부는 기존 extract_source_candidates. 의도를 낱말 모드로 축약하지 않는다.
   - save: 출처가 있고 저장 요청일 때. 요약·번역·「원문 유지」가 있으면 keep_original=True.
     「요약만」「원문은 빼/없이/삭제」일 때만 keep_original=False, summarize=True.
     출처가 없는 「저장한」은 save 가 아니다.
   - reprocess: target 이 있고, 원문 유지·정리·요약·문단 번역을 요청할 때. 「위키」가 없어도 된다.
   - open: 노트를 열라는 요청. 화면만 여는 완전 일치 문장은 None.
   - delete: 삭제·지워. 「없애지/지우지/삭제하지」는 삭제가 아니다. 위키·노트·문서 또는 직전 노트.
   - create: 새 노트 작성. title, body.
   - update: 직전 노트의 제목 또는 본문을 바꾸는 요청. 정리·번역이면 reprocess.
   - list: 위키 노트 목록.
   - 직전 답변을 저장하라는 기존 한 문장은 save + content 로 유지.

3) 실행 (iris/knowledge/wiki_ops.py)
   execute_wiki_command(wiki, command, *, summarize_fn, translate_fn, filing) -> dict
   - save + raw: 기존 import_to_wiki 또는 save_answer_to_wiki. 모델 없음.
   - save + keep_original: 추출 본문 유지. summarize 면 요약은 위, 원문은 아래.
     translate 면 문단마다 한국어를 원문 문단 아래에 붙인다. 같은 글을 file_user_note 로 쓴다.
   - reprocess: target 노트를 읽고, 이미 ## 원문 이 있으면 그 문단(번역 인용 제외)을 원문으로 쓴다.
     순서: 읽기 → summarize_fn 한 번 → 문단 번역 → 요약, 원문, 문단 번역 → 같은 rel_path 에 쓰기.
     번역 호출은 문단당 하나, 상한 24. 넘는 문단은 원문만 남긴다.
   - open: 경로만 돌려준다. 화면 열기는 호출자.
   - delete: 사용자 노트 파일만 삭제. docs 볼트는 삭제하지 않는다.
   - create: 새 노트. update: 같은 경로의 제목 또는 본문.
   - list: 제목 목록 문자열.
   반환: op, rel_path, path, title, wrote, opened, changed, mode, body(저장 본문이 필요하면).
   채팅 문장은 모델이 쓰지 않는다.

4) 세션 대상
   MainWindow._wiki_last_rel. 저장·재가공·생성·변경 성공 시 갱신. 그 노트를 삭제하면 비운다.
   대화 전환·세션 비우기에서 비운다. __init__ 에서 "" 로 만든다.

5) 완료 문장 (iris/knowledge/wiki_claim.py)
   settle_wiki_claim(text, *, goal, wrote, opened, changed) -> str
   - 이번 사용자 목표가 위키 작업이 아니면 text 를 그대로 둔다. 코드 파일 게이트와 섞지 않는다.
   - 「저장했·정리했·덮어·번역해 두었·삭제했·변경했」인데 이번 턴 쓰기(wrote)가 없거나
     파일 변경이 명시적으로 거짓이면 "노트는 그대로다" 만 반환.
   - 열기 주장(「열었」「열어 드」)은 목표에 위키·노트·문서·원문이 있을 때, opened 일 때만 그 문장을 둔다.
     아니면 "노트를 열지 못했다."
   _gate_chat_completion 에서 파일 게이트보다 먼저 적용한다.

6) 도구 진행 (iris/infrastructure/hermes_client.py _format_tool_progress)
   tool/name/tool_name/action 이 있으면 status 보다 앞에 둔다.
   예: {"tool":"wiki.write_user_note","status":"completed"} → "wiki.write_user_note completed"
   status 만 있으면 그 문자열. counts_as_tool_ok 는 여전히 " ok" 만 성공이다.
   completed/running 은 성공이 아니다.

7) 턴 감독 (iris/runtime/turn_followthrough.py)
   목표에 원문·문단·번역·덮어, 또는 (위키|노트|wiki|가져오) 와 (저장|정리|번역|요약|열기|삭제) 가 있으면
   위키 작업이다. tool_ok_count==0 이고 답이 저장·정리·덮어·번역·열기 완료면 continue.
   날씨처럼 그 목표가 아니면 stop.
   continue 이고 목표가 WikiCommand 로 파싱되며 성공이 0이면, 모델에게 도구를 다시 시키지 말고
   그 사용자 문장을 한 번 더 로컬 명령으로 돌린다. 상한은 기존 CAP.

8) 컨트롤 액션 (iris/ui/control_actions/wiki.py)
   - wiki.read_note: rel_path 본문. 모델이 파일을 읽을 수 있게.
   - wiki.reprocess_note: 위 재가공 절차 한 번. UI 스레드에서 돌리지 않는다
     (control_surface._OFF_UI_ACTIONS). 화면 열기는 UI 스레드로 마샬.
   - wiki.delete_note: 사용자 노트 삭제.
   wiki.import_content raw 는 유지.

9) 채팅 연결 (iris/ui/window/main_window.py, 붙이는 코드는 iris/ui/wiki_turn.py)
   턴 시작 시 위키 쓰기/열기 표시를 끈다. Hermes 분기보다 먼저 parse 가 명령을 주면 실행하고 반환.
   모델이 필요한 save/reprocess 는 QThread. 슬롯은 예외를 삼킨다.
   성공 답은 경로가 있는 기존 저장 안내 또는 동작별 한 줄(열었습니다, 삭제했습니다, 목록).
   거짓 완료 뒤에 자동으로 같은 문장을 다시 넣는 경로는 7번.

10) 확인
   python -m iris.knowledge.wiki_command
   python -m iris.knowledge.wiki_ops
   python -m iris.knowledge.wiki_claim
   python -m iris.runtime.turn_followthrough
   python -m iris.ui._check_content_extract
   python -m iris.ui._check_wiki_save_intent
   python -m iris.infrastructure.hermes_client
   재현:
   - 주소와 「위키에 저장」→ raw 노트, 답에 경로.
   - 직후 「원문은 남기고 위에 정리, 문단 아래 한국어」→ 같은 파일에 한국어 요약, 원문, 문단 번역.
   - 쓰기가 없는데 「정리했습니다」→ 화면에는 「노트는 그대로다」만.
```
