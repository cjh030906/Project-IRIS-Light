# 채팅 요청 직후 Iris 종료 (0xC0000409) 종합


| 항목    | 내용                                                                           |
| ----- | ---------------------------------------------------------------------------- |
| 문서 번호 | IRIS-REV-2026-0930-03                                                        |
| 작성일   | 2026-09-30                                                                   |
| 대상    | Windows에서 `pythonw.exe`가 `Qt6Core.dll`에서 죽는 종료                               |
| 목적    | 같은 증상으로 보인 종료를 시각·원인·조치로 가르고, 다음 재발 때 확인 순서를 고정한다                            |
| 근거    | WER `Report.wer`, `%USERPROFILE%\.iris-light\iris_light.db`, 소스 주석, 당일 수정 기록 |


Windows 이벤트와 WER의 예외 오프셋이 같아도 원인이 하나인 것은 아니다. `Qt6Core.dll+0x1cf68`, 코드 `c0000409`, 데이터 `7`, 종류 `BEX64`는 Qt가 `qFatal`로 프로세스를 끊는 자리이다. Python 예외가 슬롯 밖으로 나가도, WebEngine 초기화 순서가 깨져도, 이 주소로 모인다.

## 1. 이번 종료 (2026-09-30 15:34:22)

아까 12시대 채팅 입력 종료와 **같은 종류**이다. 같은 모듈, 같은 오프셋, 같은 코드이다. 빠진 변수는 다르다.


| 시각       | 사실                                                                                    |
| -------- | ------------------------------------------------------------------------------------- |
| 15:34:21 | 대화 7 사용자 메시지. 본문은 `https://rl.ai.jiny.dev/01_강화학습이란`                                  |
| 15:34:22 | 같은 대화에 비서 메시지 「위키에 저장했습니다.」가 저장된 뒤 프로세스 종료                                            |
| WER      | `AppCrash_pythonw.exe_…3c797cf2-…`, `Qt6Core.dll` 6.11.1.0, 오프셋 `0x1cf68`, `c0000409` |


위키 저장 자체는 끝까지 갔고, 성공 문구도 DB에 남았다. 그 다음 `_finish_current_turn(turn.id)`가 필수 키워드 `open_followup` 없이 호출됐다. 시그니처는 `*, open_followup: bool`라서 `TypeError`가 났다. 이 호출은 사용자 턴 슬롯 안에 있다. PyQt6는 슬롯에서 처리되지 않은 예외가 나면 오류 창 없이 `qFatal`을 부르고, Windows는 그것을 `0xC0000409`로 기록한다.

조치: `open_followup` 기본값을 `False`로 두었다. 음성 이어 듣기는 호출부가 `open_followup=True`에 해당하는 값을 직접 넘긴다. 위키 경로는 넘기지 않으므로 마이크를 다시 열지 않는다. 회귀는 `python -m iris.ui._check_turn_followup`에서 키워드 없이 `_finish_current_turn`을 호출한다.

## 3. 다음에 같은 종료가 보이면

1. 이벤트 뷰어 또는 `C:\ProgramData\Microsoft\Windows\WER\ReportArchive\AppCrash_pythonw.exe_*`에서 모듈이 `Qt6Core.dll`, 코드가 `c0000409`, 오프셋이 `0x1cf68`인지 본다.
2. 그 시각과 `iris_light.db`의 `chat_messages.created_at`을 맞춘다. 행이 없으면 전송 슬롯 초입(속성 없음, 시그니처 불일치)이다. 행이 있으면 그 기록 직후 호출(`_finish_current_turn`, 화면 전환, 게이지 갱신)이다.
3. `%LOCALAPPDATA%\iris-light\launcher.log`가 비어 있으면 Python traceback이 디스크에 안 남은 것이다. 슬롯 예외는 콘솔 없는 `pythonw`에서 사라진다.
4. 고칠 때는 슬롯이 예외를 밖으로 내지 않게 한다. 키워드 전용 인자는 기본값을 둔다. 새 필드는 `MainWindow.__init__`에서 만든다.
5. WebEngine, `nativeEvent`, `QAbstractNativeEventFilter`, `WNDPROC`, 생성자 `winId()`, `--use-gl=desktop`, frameless 창의 modal 자식은 이 코드의 다른 입구이다. 채팅 슬롯 수정으로 막히지 않는다.

회귀 확인:

```powershell
.venv\Scripts\python.exe -m iris.ui._check_turn_followup
```
