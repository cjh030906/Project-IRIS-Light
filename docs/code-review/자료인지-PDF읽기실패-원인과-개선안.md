# 자료 인지 실패(PDF·폴더·링크) 원인 및 개선안

| 항목 | 내용 |
|---|---|
| 문서 종류 | 코드 검토 보고 |
| 작성일 | 2026-10-01 |
| 검토 대상 | 채팅 턴의 파일·폴더·URL 인지 (`iris/ui/window/main_window.py`, `iris/ui/chat/at_path_refs.py`, `iris/knowledge/content_extract.py`, Hermes 시스템 지침) |
| 범위 밖 | 위키 저장분 RAG. 해당 건은 별도 개선 중 |

---

## 1. 목적

사용자가 채팅에 PDF, 폴더, 파일, 링크를 넘겼을 때 아이리스가 그 내용을 읽고 설명하게 하는 최소 개선을 정한다.

검토 근거는 2026-10-01 대화다. 사용자는 `@D:/Downloads/01_자료구조의 이 자료를 파악하고 뭔지 간단하게 설명해줘`라고 보냈다. 아이리스는 `01_자료구조의 이해.pdf`가 있다고 확인한 뒤, PDF 본문은 읽을 수 없다며 페이지 캡처를 요청했다.

---

## 2. 검토 결과

본문을 뽑는 기능은 이미 있다. 채팅이 그 기능을 쓰지 않는다.

`content.extract`(`extract_from_source`)는 다음을 텍스트로 만든다.

- PDF: `pypdf`로 글자를 뽑고, 글자가 없으면 PyMuPDF 렌더 후 Tesseract OCR
- http(s) URL
- `.md` `.txt` `.csv` `.json` `.log`, 확장자 없는 파일
- 상한 8만 자

같은 함수가 `wiki.import_content`에도 연결되어 있다. 위키에 저장하라고 하면 PDF를 읽을 수 있다. “이게 뭐야”에는 그 경로가 없다.

채팅이 모델에 넘기는 것은 경로 문자열뿐이다.

```3185:3191:iris/ui/window/main_window.py
    def _format_user_turn_content(self, turn: UserTurn) -> str:
        text = (turn.text or "").strip()
        if not turn.attachments:
            return text
        lines = "\n".join(f"- `{p}`" for p in turn.attachments)
        block = f"[첨부 파일]\n{lines}"
        return f"{text}\n\n{block}" if text else block
```

`@경로`는 IDE가 붙어 있을 때 파일을 여는 용도다. 본문을 프롬프트에 넣지 않는다. 경로 정규식은 공백에서 끊긴다. `@D:/Downloads/01_자료구조의 이해.pdf`는 `D:/Downloads/01_자료구조의`까지만 잡히고, 그 경로는 파일이 아니다.

시스템 지침과 `iris-wiki` 스킬은 PDF 추출을 “위키에 저장”할 때만 말한다. 반대편 문장은 “PDF로 저장해 달라”는 요청에 터미널·PyMuPDF·reportlab을 쓰지 말라는 것이다. 모델을 죽이는 생성 금지가, 이번 답변에서는 “PDF는 읽을 수 없다”로 나왔다.

이미지는 “이 화면을 코드로 옮겨”일 때만 비전 입력으로 간다. 폴더 칩은 붙일 수 있으나 `extract_from_source`는 파일이 아니면 거부한다. `.py` `.html` `.docx` `.pptx` `.xlsx`도 같은 함수가 거부한다.

## 3. 원인

| 번호 | 원인 | 이번 증상과의 관계 |
|---|---|---|
| 1 | 설명 요청 턴에 본문 추출이 없다 | 모델은 파일명만 보고 답한다 |
| 2 | 추출 도구 안내가 위키 저장에만 있다 | `content.extract`를 호출하지 않고 캡처를 요구한다 |
| 3 | `@` 경로가 공백·접두어에서 끊긴다 | `01_자료구조의`는 파일이 아니다. 이어서 폴더를 뒤져 파일명만 맞춘다 |
| 4 | 폴더·코드·오피스·일반 이미지는 추출 대상이 아니다 | PDF를 고쳐도 나머지 자료는 같은 방식으로 실패한다 |

모델이 PDF 라이브러리를 모른 것이 아니다. 읽을 텍스트가 턴에 없고, 읽으라는 지시가 없다.

---

## 4. 개선안

모델이 도구를 떠올리기에 기대지 않는다. 답을 만들기 전에 아이리스가 본문 발췌를 턴에 붙인다.

1. **채팅 턴에 발췌를 붙인다.** 첨부 칩, 해석이 끝난 로컬 경로, 메시지 안의 http(s)를 `extract_from_source`로 읽는다. 사용자 메시지 뒤에 `[자료 본문]`으로 붙인다. 채팅 발췌 상한은 위키 8만 자보다 짧게 두고, 잘렸으면 그 사실을 같이 적는다. 추출이 실패하면 실패 이유만 적는다. 캡처를 먼저 요구하지 않는다.
2. **경로를 파일까지 맞춘다.** 공백이 있는 파일명을 한 덩어리로 본다. `D:/Downloads/01_자료구조의`처럼 파일이 아니면, 그 폴더에서 이름이 그 문자열로 시작하는 파일이 하나일 때만 그 파일을 읽는다. 여러 개면 이름 목록만 보여주고 본문은 넣지 않는다.
3. **폴더는 목록과 일부만 읽는다.** 바로 아래 파일 이름과, 텍스트·PDF 소수만 발췌한다. 하위 폴더 전체를 한 턴에 넣지 않는다.
4. **지침 한 줄을 나눈다.** “자료가 무엇인지 설명해 달라”는 `content.extract`로 읽는다. “PDF 파일로 저장해 달라”만 터미널·PyMuPDF·reportlab 금지를 유지한다. 두 문장을 한 줄에 두지 않는다.
5. **형식은 두 단계로 늘린다.** 1단계는 지금 되는 PDF·URL·일반 텍스트를 채팅에 연결하는 것이다. 2단계는 `.py` `.html`처럼 글자로 열리는 파일, `.docx`, 그리고 설명 요청 이미지를 기존 비전 입력에 태우는 것이다. 한글(HWP)은 추출기가 생기기 전에는 미지원이라고 답한다.

하지 말 것: 모델에게 셸로 `pypdf`·PyMuPDF를 실행하게 하기. 그 경로는 프로세스를 끝내는 쪽으로 이미 막혀 있다.

---

## 5. 확인 기준

- `@D:/Downloads/01_자료구조의 이해.pdf`와, 그 폴더에 접두가 하나뿐인 `@D:/Downloads/01_자료구조의` 모두 본문 발췌가 턴에 들어간다.
- 같은 PDF를 “위키에 저장”하지 않고 “뭔지 설명해 줘”만 해도, 답은 파일명이 아니라 쪽 내용에서 나온다.
- 폴더를 넘기면 파일 목록이 먼저 나오고, 그중 문서 일부만 요약된다.
- http(s) 링크를 “파악해 줘”라고 하면 페이지 글자가 턴에 들어간다.
- “이 대화를 PDF로 저장해 줘”는 지금처럼 아이리스 저장만 하고, 모델이 PyMuPDF를 실행하지 않는다.
