# Prompt: 채팅 자료 본문 (PDF·폴더·링크·스캔 이미지)

아래 블록을 구현 계약으로 따른다. 보고서: `docs/code-review/자료인지-PDF읽기실패-원인과-개선안.md`

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- 본문 추출은 이미 있다. extract_from_source (content.extract) 가 PDF·URL·텍스트를 읽고,
  wiki.import_content 만 그 함수를 탄다. 채팅의 “이게 뭐야”는 경로 문자열만 모델에 넘긴다.
- 기본 창과 IDE Companion 은 같은 MainWindow._execute_user_turn 이다. 둘 다 여기서 읽는다.
- @경로는 iris/ui/chat/at_path_refs.py 가 공백에서 끊긴다.
  @D:/Downloads/01_자료구조의 이해.pdf 는 D:/Downloads/01_자료구조의 만 남고, 그 경로는 파일이 아니다.
- PDF 글자 층이 없으면 이미 PyMuPDF 렌더 + Tesseract(kor+eng) OCR 이 있다.
  채팅이 호출하지 않고, Tesseract 가 없거나 결과가 비면 모델은 캡처를 요구한다.
- “PDF로 저장”은 note.export_pdf / 로컬 pdf_export 다.
  모델이 PyMuPDF·reportlab·pdf_create.py 를 직접 돌리면 프로세스가 죽는다.
- 화면의 You 말풍선은 짧게 둔다. 모델이 보는 히스토리에만 [자료 본문]을 붙인다.
- 새 pip 패키지 없음. docx/pptx/xlsx 는 zip 안 XML 이다.

Goal:
1) 답을 만들기 전에 아이리스가 자료를 읽어 사용자 메시지 뒤에 [자료 본문]을 붙인다.
   대상: 첨부 칩, 해석이 끝난 @경로, 메시지 안의 http(s). 기본 창과 IDE Companion 모두.
2) 공백 있는 파일명을 한 덩어리로 잇는다. 파일이 아니면 그 폴더에서
   이름이 그 문자열로 시작하는 파일이 하나일 때만 그 파일을 읽는다.
   여러 개면 이름 목록만 넣고 본문은 넣지 않는다.
3) 폴더는 바로 아래 이름(최대 40)과 텍스트·PDF·오피스 소수(최대 3)만 발췌한다.
   하위 폴더 파일은 넣지 않는다.
4) 채팅 발췌 상한은 12000자. PDF는 앞 8쪽. URL은 3개, 자료는 한 턴 6개.
   잘렸거나 쪽을 덜 읽었으면 그 사실을 적는다. 실패하면 이유만 적고 캡처를 요구하지 않는다.
5) 지침을 두 문장으로 나눈다.
   자료가 무엇인지 설명해 달라는 [자료 본문]으로 답한다.
   “PDF 파일로 저장·만들어 달라”만 note.export_pdf 이고, 터미널·PyMuPDF·reportlab 금지를 유지한다.
6) 형식: 지금 되는 PDF·URL·일반 텍스트에 더해 .py .html 처럼 글자로 열리는 파일,
   docx/pptx/xlsx(zip XML), 설명 요청 이미지(기존 비전 호출)를 읽는다.
   사진을 코드 파일로 쓰라는 요청은 기존 project.write_image_code 에 맡기고 여기서 비전을 또 부르지 않는다.
   한글(HWP/HWPX)은 미지원이라고 적는다.
7) 글자 층이 없는 이미지 PDF(스캔·슬라이드 연속)도 읽는다. 아래 “이미지 PDF” 순서.

이미지 PDF (쪽마다):
- pypdf 글자(한글·영문·숫자)가 40자 이상이면 그 글자를 쓴다. OCR을 하지 않는다.
- 그보다 짧으면 그 쪽은 이미지로 본다. PyMuPDF로 PNG를 만들고 Tesseract kor+eng OCR을 한다.
  OCR 글자가 8자 이상이면 그 글자를 쓴다.
- OCR이 비었거나 Tesseract가 없으면, 그 PNG를 최대 4장까지 이미 선택된 채팅 모델의
  비전 입력으로 한 번 보내 글자를 옮긴다. 프롬프트는 “보이는 글자를 페이지 순서대로 옮겨 적어라.
  글자가 없으면 그림이 무엇을 보여 주는지 짧게 적어라. 없는 내용은 만들지 마라.”
  Ollama는 chat_once_with_images, API 모델은 기존 이미지 코드 추출과 같은 chat/completions image_url.
- 비전 결과도 비면 실패 이유(Tesseract 없음, 비전 빈 응답)만 [자료 본문]에 적는다.
  사용자에게 페이지 캡처를 먼저 요청하지 않는다.
- 위키 저장 경로(extract_from_source 기본 호출)는 비전 없이 글자 층과 OCR만 한다.
  채팅만 vision_reader를 넘긴다. 모델이 셸로 pypdf·PyMuPDF를 실행하게 하지 않는다.

Constraints:
- 채팅 로그를 메시지 위젯 목록으로 바꾸지 말 것. You 말풍선에는 발췌 전문을 넣지 말 것.
- 추출은 UI 스레드 밖에서. 읽는 동안 생성 중으로 두고, 턴이 바뀌면 결과를 버리지.
- Companion 80:20, IDE new-window, note.export_pdf 자식 프로세스 계약을 유지.
- “이 대화를 PDF로 저장”은 발췌를 붙이지 않는다. is_pdf_save_intent 이면 읽지 않는다.
- Surgical: 아래 파일과 자검만.

Interface:
1) iris/ui/chat/at_path_refs.py
   - extract_at_path_refs 가 @ 뒤 토큰을 공백 너머로 잇는다.
     다음 단어를 붙인 경로가 파일이거나, 그 폴더의 어떤 파일 이름이 그 이름으로 시작할 때만 잇는다.
   - IDE로 여는 resolve_at_path 의 “폴더면 None”은 유지한다.

2) iris/knowledge/content_extract.py
   - read_pdf_pages(path, *, page_limit=None, vision_reader=None)
     → {text, ocr_used, vision_used, note}. 본문이 없으면 ValueError.
   - extract_pdf_text 는 read_pdf_pages 를 쓴다. 비전은 넘기지 않는다.
   - extract_from_source(source, *, char_limit=80000, page_limit=None, vision_reader=None)
     PDF는 read_pdf_pages. 글자 파일에 코드·html 확장자를 포함한다.
     docx/pptx/xlsx 는 zip XML의 텍스트 노드. png 등 이미지는 vision_reader 가 있을 때만.
     hwp/hwpx 는 “한글(HWP) 파일은 아직 본문을 읽지 못합니다.”
   - 위키 호출 인자 추가는 없다. 기존 위치 인자는 그대로다.

3) iris/knowledge/page_vision.py
   - transcribe_images(pngs, *, model, ollama_base_url, api_base_url="", api_key="", auth_style="bearer") -> str
   - 위 비전 프롬프트. 이미지는 PNG 바이트.

4) iris/knowledge/material_excerpt.py
   - CHAT_EXCERPT_CHARS=12000, CHAT_PDF_PAGES=8, MAX_SOURCES=6, MAX_URLS=3,
     FOLDER_LIST_CAP=40, FOLDER_READ_CAP=3
   - extract_http_urls(text)
   - turn_should_read_materials(text, attachments, *, bases=(), skip_image_files=False) -> bool
     PDF 저장 의도이거나 읽을 자료가 없으면 False.
   - build_material_block(...) -> str
     읽을 것이 없으면 "". 있으면 "[자료 본문]"으로 시작한다.
     파일은 ### 제목, 경로, 읽기 방식(OCR/이미지), 본문.
     잘리면 "잘림: 채팅 발췌 상한에서 끊었습니다."
     접두가 여러 개면 이름만. 폴더는 바로 아래 목록 후 소수 발췌.
     실패는 "(읽지 못함) 이유".
   - compose_model_user_text(display, block) -> str

5) iris/ui/workers/material_read_worker.py
   - QThread. run 에서 build_material_block. 예외도 [자료 본문] 실패 문장으로 emit.

6) MainWindow
   - You 말풍선은 _format_user_turn_content 그대로.
   - turn_should_read_materials 이면 "자료를 읽는 중…" 후 워커.
     끝나면 compose 한 문자열만 _record_history("user", ...) 에 넣고 기존 채팅 발사로 이어간다.
   - 비전 spec 은 선택된 모델(Ollama 또는 API provider)이다. Hermes 여부와 무관하게 발췌는 앱이 붙인다.
   - 검색 기준 경로는 IDE 워크스페이스, project_root, project_parents, 최근 폴더.
   - _chat_messages_with_project_context: “자료 설명은 [자료 본문]으로 답하고 캡처를 먼저 요구하지 않는다”와
     “PDF 파일로 저장만 note.export_pdf, PyMuPDF·reportlab·pdf_create.py 금지”를 서로 다른 문장으로 둔다.
   - content.extract 카탈로그 요약에, 채팅은 이미 [자료 본문]을 붙인다고 적고 action_catalog.json 을 맞춘다.

7) 지침 사본
   - hermes_memory_nudge 마커를 v18로 올리고, [자료 본문]으로 답하라는 한 줄과
     PDF 저장 금지를 저장 문장 쪽에만 둔다.
   - integrations/hermes-skills/iris-control/iris-wiki/SKILL.md:
     설명 요청은 위키 저장이 아니고 [자료 본문]으로 답한다. 캡처를 먼저 요구하지 않는다.

8) 자검 iris/ui/_check_material_excerpt.py
   - 공백 경로 @…/01_자료구조의 이해.txt 와, 접두가 하나인 @…/01_자료구조의 모두 본문에 그 파일 문장이 있다.
   - 접두가 두 개면 본문 문장은 없고 두 파일 이름만 있다.
   - 폴더는 바로 아래 txt 본문만 있고, 하위 폴더 파일 문장은 없다.
   - http URL 은 fetch 를 갈아 끼우면 그 글자가 블록에 있다.
   - .py 와 최소 docx(zip) 본문이 들어간다. .hwp 는 한글 미지원 문장.
   - 글자 없는 PDF(이미지 1쪽)는 OCR을 빈 문자열로 갈아 끼우면 vision_reader 문장이 들어가고 vision_used 다.
     글자 층이 충분한 PDF는 vision_reader 를 부르지 않는다.
   - "이 대화를 PDF로 저장해 줘" 는 읽지 않는다.
   - 12000자를 넘기면 잘림 문장이 있다.
```
