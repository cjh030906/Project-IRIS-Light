# Prompt: 채팅 칸 다이어그램 카드

아래 블록을 구현 계약으로 따른다. 보고서: `docs/code-review/채팅다이어그램카드-현황과-archify-보고서.md`

```text
Context:
- 저장소: Project-IRIS-Light (Windows / PyQt6)
- 렌더 경로는 이미 있다. diagram.render → archify_render.render_diagram → open_diagram_preview.
- open_diagram_preview 는 최상위 QWebEngineView 창을 띄운다 (iris/ui/window/diagram_preview.py).
- 채팅 로그는 ChatPanel 의 QTextEdit 하나다 (iris/ui/chat/chat_panel.py). 문서 안에 웹뷰를 넣지 않는다.
- archify HTML 은 ?present=1 이면 SVG 를 뷰포트에 맞추고 테마(#btn-theme)·경로(#btn-route-probe)를 남긴다.
  ?embed=1 은 그 버튼을 숨기므로 쓰지 않는다.
- present 모드 헤더 padding-right: 23rem 은 좁은 칸에서 제목을 민다.
- WebEngine 은 QApplication 이후 첫 사용 때 생성한다 (qt-webengine-bootstrap.mdc). 부모 없는 창 금지.
- 액션 카탈로그 스냅샷 iris/ui/control_actions/action_catalog.json 은 register() 요약과 같아야 한다.

Goal:
1) diagram.render 성공 시 별도 창 대신 채팅 로그와 입력창 사이의 카드에 뷰어를 연다.
2) 카드 너비는 채팅 칸, 높이는 패널 높이의 절반(180~420, 높이 0이면 280). 웹뷰는 하나 재사용.
3) 첫 화면은 present=1 로 다이어그램 전체가 카드 안에 들어오게 한다. 테마·경로 버튼은 페이지 안에 둔다.
4) 닫기 후에도 로그의 "다시 보기"로 같은 HTML 을 연다.
5) 모델은 사용자가 구조·흐름·시퀀스·아키텍처를 부탁할 때, 또는 여러 모듈 구조 변경을 설명·요약할 때만 diagram.render 를 호출한다. 한 턴에 한 번. 작은 수정·버그 수정·실행 결과에는 호출하지 않는다. architecture-diagram 스킬로 HTML 을 쓰지 않는다.

Constraints:
- integrations/archify/ 수정 금지. 새 pip 패키지·스킬 설치 금지.
- 채팅 로그를 메시지 위젯 목록으로 바꾸지 말 것.
- Companion 80:20, IDE new-window, 기존 project.write_file 계약 유지.
- Surgical: 아래 파일과 자검만.

Interface:
1) iris/ui/chat/diagram_card.py
   - card_height_px(panel_height: int) -> int
   - present_file_url(path) -> QUrl. 로컬 파일 + query present=1. embed 없음.
   - diagram_href / parse_diagram_href. 스킴 iris-diagram://, quote 왕복.
   - DiagramCard(QFrame). 부모 필수. 제목 줄 + 닫기 + 웹뷰.
     웹뷰는 show_file 때 생성. loadFinished 에서 data-present 를 보장하고
     헤더 padding-right 만 0으로 덮는 스타일 한 개를 넣는다.
     Window 플래그를 세우지 않는다.

2) ChatPanel
   - show_diagram(html_path, title="") -> bool. 파일 없으면 False.
     카드를 로그와 입력 사이에 넣고 card_height_px(self.height()) 로 높이를 고정한 뒤 표시.
   - append_diagram_note(html_path, title=""). 화자·TTS 없이
     "{제목 또는 구조도} · 다시 보기" 링크. href 는 diagram_href.
   - resizeEvent 에서 카드가 보이면 높이를 다시 계산.
   - ChatLogTextEdit 가 iris-diagram:// 를 누르면 show_diagram.

3) open_diagram_preview(window, html_path, title="") -> bool
   - window._chat.show_diagram 이 성공하면 append_diagram_note 후 True.
   - 채팅이 없거나 파일이 없으면 False. 최상위 창을 만들지 않는다.
   - diagram_render 가 title 을 넘긴다.

4) 안내 문장
   - main_window._chat_messages_with_project_context 의 제어 문단에 Goal 5 를 넣는다.
   - diagram.render 카탈로그 요약에도 같은 호출 조건과 "채팅 칸, 별도 창 아님, architecture-diagram 스킬 금지"를 넣는다.
   - action_catalog.json 요약을 register() 와 같게 고친다.

5) 자검 iris/ui/_check_diagram_card.py
   - card_height_px: 0→280, 200→180, 800→400, 2000→420.
   - present_file_url 에 present=1 이 있고 embed 는 없다.
   - href 왕복.
   - 가짜 채팅으로 open_diagram_preview: 있는 파일은 카드 호출+노트, 없는 파일과 _chat 없음은 False.
   - WebEngine 을 생성하지 않는다.

검증:
.venv\Scripts\python.exe -m iris.ui._check_diagram_card
.venv\Scripts\python.exe -m iris.ui._check_control_action_split
```
